# Milestone 11 — Orphaned SwiftData write-repository removal

This focused removal follows merged M11 PR #127. The active app already composes all Animal, Herd and Pasture dependencies with Core Data, so these **three orphaned repositories** can be removed without editing the runtime, permanent Core Data contracts or recovery.

## Dependency inventory and deletion boundary

- **Remove:** `yaHerd/Data/Repositories/SwiftDataAnimalRepository.swift`, `SwiftDataHerdRepository.swift`, and `SwiftDataPastureRepository.swift`.
- **No remaining live callers:** repository searches locate each class only in its own file and `yaHerd/App/Persistence/SwiftDataPersistenceAssembly.swift`, which PR #127 removed. These files declare only their respective repository type/private extension, not shared Domain utilities.
- **Keep:** `CoreDataAppPersistenceAssembly`, `CoreDataAnimalRepository`, `CoreDataHerdRepository`, `CoreDataPastureRepository`, M9 readers, application mutation wrappers, every Core Data contract, and all original legacy models/schema and recovery.
- **Keep test-dependent SwiftData repositories:** `SwiftDataFieldCheckRepository` is referenced by `FieldCheckHistoricalSnapshotTests`; `SwiftDataTagColorRepository` by `TagColorLibraryStoreTests`; `SwiftDataWorkingRepository` by `WorkingTreatmentDoseSchemaTests`. Their related lookup/write helpers must be handled with their test contracts later, not broken here.
- **Keep original data:** current Core Data preflight recognizes `yaHerdStore.store`, `yaHerdStore.sqlite`, `default.store` and journal sidecars; the in-memory recovery/export still preserves original database bytes. **No legacy-to-Core Data record migration exists yet**; that remains a release-upgrade blocker.
- **Build context:** `yaHerd.xcodeproj` uses filesystem-synchronized `yaHerd` and `yaHerdTests` groups. Source deletion naturally removes target membership without editing the Xcode project.

## Delegated Milestone 11 work

The remaining SwiftData Field Check, Tag Color, Working and helper graph is intertwined with explicit legacy tests. Before deleting those files, route the test behaviors to their already-existing permanent Core Data contracts or remove obsolete duplicate implementation tests without weakening permanent behavior coverage. The `Data/Models`, `Data/Persistence/Schema`, `DefaultHerdBootstrapper`, `ModelContainerFactory`, `SampleLargeDataService` and `TestSupport` dependencies require a separate complete inventory. Do not discard farm seed source data or change persisted legacy SQLite/sidecar files in a cleanup PR.

No build, test, lint or CI verification commands are manually run under `AGENTS.md`. Self-review uses call-graph and GitHub-diff inspection only.
