# Milestone 11 — Retire dormant SwiftData Working adapter after Core Data contract parity

Created before executable source deletion. The active M10 dependency graph is Core Data-only. Source/caller searches identified the remaining `SwiftDataWorkingRepository`, its private lookup/writer/session/ID helpers and extensions as a closed, inactive adapter family. Its only executable client is `yaHerdTests/WorkingTreatmentDoseSchemaTests.swift`.

## Dependency and permanent contract inventory

- **Remove:** `SwiftDataWorkingRepository.swift`, `SwiftDataWorkingRepository+SessionStart.swift`, `+SessionTreatments.swift`, `+TagReplacement.swift`, `SwiftDataWorkingLookupStore.swift`, `SwiftDataPublicIDUniquenessStore.swift`, `SwiftDataWorkingWorkDataWriter.swift`, `SwiftDataWorkingSessionCleanupWriter.swift`, `SwiftDataWorkingSessionCompletionPlan.swift` and duplicate `WorkingTreatmentDoseSchemaTests.swift`; remove `WorkingMapper.swift` after its last consumers are gone.
- **Retain:** the active Core Data `WorkingMapper` implementation by making the existing `WorkingMapper+CoreData.swift` extension the namespace declaration; delete the unused SwiftData-model overload file `WorkingMapper.swift`. Legacy models, model schema, migration plan, ModelContainer factory, TestSupport, seed sources, original store and recovery/preflight remain untouched.
- **Permanent Core Data contract owners:** the existing `CoreDataWorkingRepositoryContractTests` executes `WorkingRepositoryContract` read/start/lifecycle, `+WorkData`, `+PlansTagsAndTemplates`, `+AtomicityRollback` assertions. The four old tests overlap respectively with structured treatment snapshot/dose identity, treatment event identity under plan edits, negative dose/duplicate planned item validation, and *obsolete SwiftData-only* queue-order state. Current `CDWorkingQueueItem` does not have the old `queueOrder` field; current queue membership, UUID and status are covered by `assertSessionStartAndReadProjections`.
- **Retain** `WorkingProtocolItem` in `WorkingTreatmentTerminologyCompatibility.swift` because `WorkingSession`, `WorkingProtocolTemplate`, and `SampleDataService` still use it; only the two obsolete SwiftData adapter return-type aliases are removed.
- **Release blocker unchanged:** no lossless SwiftData-to-Core Data existing-user record import exists. Recognized legacy stores are still protected by `CoreDataLegacyStorePreflight` and recovery/export; no legacy file may be overwritten/deleted. This PR does not satisfy the existing-user upgrade gate.
- **No SwiftData investment:** no new legacy fixtures, migration adapters, tests or runtime fallback are introduced. Existing Core Data contracts are the maintained behavior owner. All verification execution remains prohibited unless explicitly requested.
