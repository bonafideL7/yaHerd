# Milestone 11 — Exclude Frozen Legacy SwiftData Sources from the App Target

## Design and ownership

After M11 PR #141 merged, 19 legacy SwiftData model, schema and compatibility sources remain compiled solely because `yaHerd` uses a filesystem-synchronized source root. The active `yaHerdApp`/`CoreDataAppPersistenceAssembly` composition no longer calls them, and the legacy set is frozen by exact Git-blob IDs. Rather than deleting or modifying these sources before an explicit existing-user upgrade decision, exclude their legacy declarations from the app target and provide the three remaining shared enums from Domain, using the already-existing `PBXFileSystemSynchronizedBuildFileExceptionSet`. Keep all archived source paths and bytes identical. Do not alter `yaHerdTests` membership, Core Data code, legacy-store detection, recovery/export, or user files.

The initial Xcode build of the exclusion exposed three shared domain enums that had been defined outside the legacy `@Model` declarations but inside frozen files: `PregnancyResult`, `WorkingSessionStatus`, and `WorkingQueueStatus`. These types remain required by current Core Data repositories, Domain snapshots, Working editors and Home queries. To preserve archived source bytes and avoid dual declarations in the app, introduce equivalent compiled Foundation-only Domain declarations with the **same raw strings, case order, and Codable/CaseIterable capabilities** (plus Sendable), while retaining the original frozen copies uncompiled. Audit all 19 frozen files for other out-of-model declarations before the edit. This is the existing compiled API being relocated, not a new persistence model or runtime path.

The `Info.plist` exception must remain; all 19 frozen files must be excluded, including the two non-import aliases. A new architecture-script check must compare the target-specific exception set with this exact scope so a later project edit cannot quietly recompile archived SwiftData. The prior M11 blob manifest remains the source of truth; the project guard derives expected paths from it rather than maintaining a second independent list. This is target **compilation isolation plus relocation of active persistence-neutral enum declarations**, not a SwiftData-to-Core Data migration and not release readiness. Preflight still blocks unsafe legacy first opens. Build and tests are not executed unless expressly requested.

## Static review boundaries

- App/Xcode: `yaHerd.xcodeproj/project.pbxproj` existing synchronized group and `yaHerd` membership exception set; Debug and Release consume the same app target membership. Keep `Info.plist` exempt.
- Archived source: 17 files under `yaHerd/Data/Models` and 2 schema/alias files under `yaHerd/Data/Persistence/Schema`. Their original paths and Git blob hashes remain pinned by PR #141.
- App/read paths: `yaHerdApp.bootstrap` and `CoreDataAppPersistenceAssembly`, M9 query actors, M4–M8 Core Data writes. The currently compiled pregnancy result, Working session status and queue status are reproduced as independent Domain types with unchanged raw values; the 19 archived files and their blob pins remain unmodified. No active SwiftData entry point may be restored.
- Recovery: `CoreDataLegacyStorePreflight` and `RecoveryModeController` unchanged; no historical data conversion. Release blocker remains the absence of a lossless existing-user upgrade.
- Verification: initial automated run 38339215763 passed architecture but failed the Swift 6 build because the three shared enums were excluded with their legacy source files; this PR now supplies independent Domain enum definitions without changing the archive. Follow-up verification result is tracked in the PR; until a completed rerun, compilation is unverified.
