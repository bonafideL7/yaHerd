# Milestone 11 — Exclude Frozen Legacy SwiftData Sources from the App Target

## Design and ownership

After M11 PR #141 merged, 19 legacy SwiftData model, schema and compatibility sources remain compiled solely because `yaHerd` uses a filesystem-synchronized source root. The active `yaHerdApp`/`CoreDataAppPersistenceAssembly` composition no longer calls them, and the legacy set is frozen by exact Git-blob IDs. Rather than deleting or modifying these sources before an explicit existing-user upgrade decision, remove **only their membership in the production app target** through the already-existing `PBXFileSystemSynchronizedBuildFileExceptionSet`. Keep source paths and bytes identical. Do not alter `yaHerdTests` membership, Core Data code, legacy-store detection, recovery/export, or user files.

The `Info.plist` exception must remain; all 19 frozen files must be excluded, including the two non-import aliases. A new architecture-script check must compare the target-specific exception set with this exact scope so a later project edit cannot quietly recompile archived SwiftData. The prior M11 blob manifest remains the source of truth; the project guard derives expected paths from it rather than maintaining a second independent list. This is target **compilation isolation**, not a SwiftData-to-Core Data migration and not release readiness. Preflight still blocks unsafe legacy first opens. Build and tests are not executed unless expressly requested.

## Static review boundaries

- App/Xcode: `yaHerd.xcodeproj/project.pbxproj` existing synchronized group and `yaHerd` membership exception set; Debug and Release consume the same app target membership. Keep `Info.plist` exempt.
- Archived source: 17 files under `yaHerd/Data/Models` and 2 schema/alias files under `yaHerd/Data/Persistence/Schema`. Their original paths and Git blob hashes remain pinned by PR #141.
- App/read paths: `yaHerdApp.bootstrap` and `CoreDataAppPersistenceAssembly`, M9 query actors, M4–M8 Core Data writes. No active SwiftData entry point may be restored.
- Recovery: `CoreDataLegacyStorePreflight` and `RecoveryModeController` unchanged; no historical data conversion. Release blocker remains the absence of a lossless existing-user upgrade.
- Verification: not run by user instruction (`AGENTS.md`); static self-review of paths, target membership and script/project diff only.
