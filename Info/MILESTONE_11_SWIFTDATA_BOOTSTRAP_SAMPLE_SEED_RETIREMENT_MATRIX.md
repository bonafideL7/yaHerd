# Milestone 11 — Retire Dormant SwiftData Herd Bootstrap and Sample Seeders

Created before source edits on `milestone-11-retire-swiftdata-bootstraps-seeds`, based on `main` after merged PR #138.

## Design and dependency boundary

- The active `yaHerdApp` runtime is `CoreDataAppPersistenceAssembly` with `CoreDataAppHerdBootstrapper`, Core Data repositories and selected-Herd identity; it never instantiates `DefaultHerdBootstrapper`.
- `SampleDataService` and `SampleLargeDataService` are SwiftData `ModelContext` fixture writers with no active caller. The Animal list still exposes optional sample-data actions, but `CoreDataAppPersistenceAssembly` explicitly sets `sampleDataSeeder: nil`. Leave the persistence-neutral `SampleDataSeeding` protocol and mutation publisher unchanged.
- `HerdScopedRecord`'s `ModelContext` extensions are used only by those removed legacy fixture writers and the dormant bootstrap. Remove the whole unused dependency cluster, not just one caller.
- `PersistenceLog` in `ReliabilityLog.swift` is only used by the retiring SwiftData sources; drop it and `import SwiftData`, retaining `ReliabilityLog` and `UserVisibleErrorMessage` signatures and behavior.
- Retain the original animal/pasture sample notes, all SwiftData model and schema declarations for subsequent M11 cleanup, current Core Data models/bootstrap/contracts, original legacy files, first-open preflight and read-only recovery/export. No user-data conversion is performed.
- Do not run builds, tests, lint, verification scripts or manually triggered CI; `AGENTS.md` forbids verification without explicit user instruction.

## Ownership and release decision

This PR owns deletion of the five dormant source components only (the four legacy SwiftData writer/helper files plus the SwiftData `PersistenceLog` wrapper in the shared reliability file). Existing Core Data repository contracts (M4–M9) and M10 bootstrap, preflight, recovery and file-export contracts remain the permanent behavior owners. Original existing-user SwiftData stores are protected but **not** losslessly imported into Core Data: shipping the replacement as an upgrade for those users remains blocked pending a separately approved, data-preserving strategy. The matrix and static call graph must be reconciled against the final diff before review; no executed verification is claimed.
