# Milestone 11 — Field Check legacy implementation and duplicate test retirement

PRs #127 and #128 removed the unused SwiftData app assembly, background read adapter, and orphaned Animal/Herd/Pasture repositories. This next PR deletes the remaining SwiftData Field Check repository and its **sole direct legacy test caller**, without touching the Core Data Field Check implementation or permanent behavior contract.

## Scope, reference inventory and data safety

- **Delete:** `yaHerd/Data/Repositories/SwiftDataFieldCheckRepository.swift` and `yaHerdTests/FieldCheckHistoricalSnapshotTests.swift`.
- **Retain:** `CoreDataFieldCheckRepository`, `yaHerdTests/CoreData/CoreDataFieldCheckRepositoryContractTests.swift`, and `yaHerdTests/RepositoryContracts/FieldCheckRepositoryContract.swift` (the latter covers all four removed legacy test behaviors).
- **Retain shared mapper:** `FieldCheckMapper.swift` declares the enum extended by `FieldCheckMapper+CoreData.swift`; `FieldCheckMapperNeedsAttentionTests.swift` still uses legacy model overloads. Remove those only in a separate mapper/test migration.
- **No user-file cleanup:** `CoreDataLegacyStorePreflight`, read-only recovery/export, original SQLite databases/journals, legacy model/schema and original seed source remain intact. **No automatic SwiftData-to-Core Data user-data migration exists yet.** That is a release-upgrade blocker.
- **Build:** `yaHerd.xcodeproj` uses synchronized source groups, so deleting these two files excludes them from their respective targets automatically; no explicit per-file PBXSourcesBuildPhase entries exist.
- **Existing permanent contract owners:** M7 Core Data Field Check repository/transaction suite owns the behaviors; M10 owns the app graph. No new SwiftData or redundant new test runner is introduced.

| `testFindingUsesAnimalAndPastureSnapshotsAfterRecordsChange` | `assertHistoricalSnapshotsSurviveLiveRecordChanges`: immutable finding tag/color and Pasture name after mutations, including open-finding projection |
| `testDamTagUsesCheckStartSnapshotAfterDamChanges` | `assertHistoricalSnapshotsSurviveLiveRecordChanges`: calf roster retains dam's original tag and color after a live dam retag |

The existing Core Data suite invokes both permanent assertions. No duplicate test needs to be added. Legacy-only SwiftData fixture declarations and all original local-data recovery protections remain available until the corresponding subsequent M11 stage.
