# Milestone 11 — Dormant SwiftData Animal Extension Retirement

Created before source deletions, based on merged PR #139 and current `main`.

## Design, caller trace and boundaries

The active app uses `CoreDataAppPersistenceAssembly`, `CoreDataAnimalRepository`, `CoreDataAnimalMutation`, `CoreDataAnimalProjection` and Domain snapshot/service APIs. The former SwiftData Animal writers, fixtures, and seed services were retired in earlier M11 PRs. The five `extension Animal` files in `Data/Models/Animal` target the legacy `YaHerdCurrentModels` alias (`YaHerdSchemaV1.Animal`). Review found that the compiled `DashboardMapper.makeAnimalRecord(from:)` still consumes its derived and display-tag properties, although the mapper has **no production caller** and is invoked only by `DashboardMapperTests`. Delete this entire legacy mapper/test dependency cluster in the same PR rather than restore SwiftData helpers. The mapper's Animal/Pasture/Working projections are independently implemented by `CoreDataReadModelActor` and the current repository contracts own their behavior. Its only `AnimalDisplayTagFormatter.displayTagNumber(for: Animal?)` consumer also disappears; preserve the actively used `displayTagNumber(from: String)` overload. `AnimalListView.restoreArchivedRecord(_:)` is a distinct `AnimalSummary` UI handler, and `CoreDataAnimalMutation.applyStatusState` is an independent Core Data implementation. Domain `AnimalTagService`, `AnimalArchiveService`, `AnimalTypeClassifier`, `AnimalAgeFormatter` and `AnimalTimelineEvent` are retained.

Delete the five dormant extensions: `Animal+ArchiveMutation.swift`, `Animal+DerivedDomain.swift`, `Animal+StatusMutation.swift`, `Animal+TagMutation.swift`, and `AnimalTimeline.swift`; also delete `Data/Mappers/DashboardMapper.swift` and `yaHerdTests/DashboardMapperTests.swift`, and remove only the unused `AnimalDisplayTagFormatter.displayTagNumber(for animal: Animal?)` overload. Preserve legacy `@Model` and `YaHerdSchemaV1` declarations, current-model aliases, all Core Data/domain source and tests, Xcode filesystem-synchronized groups, first-open preflight, read-only Recovery Mode and TAR export. No record conversion, migration, file deletion or new fallback is performed. **Historical SwiftData records have not been losslessly imported; this remains a release blocker.**
