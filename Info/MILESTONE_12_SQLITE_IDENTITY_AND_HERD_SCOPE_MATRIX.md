# Milestone 12 — SQLite Application Identity and Herd-Scope Integration

## Design, existing owners, and scope

The Core Data model declares required UUID identifiers; `CoreDataLookup.herd` checks for store-global duplicate Herd IDs, while `CoreDataLookup.herdOwned` first resolves the Herd uniquely and then resolves a child ID *within that Herd*. The existing `CoreDataPersistenceFoundationTests` exercise these cases against in-memory Core Data contexts; the first SQLite identity test checks a new context in the same assembly, not a separately reopened coordinator. This Milestone 12 slice verifies the physical, durable interpretation of those existing identity rules by saving to the production SQLite assembly, then reopening the same store read-only and querying through the real lookup functions.

- **This PR owns:** durable UUID/Herd identity lookup at the physical SQLite reopen boundary, including stable identity, store-global ambiguous Herd roots, same-Herd ambiguous child identity and identical child UUIDs belonging to different Herds.
- **Existing owners:** `CoreDataLookup` implements the lookup semantics. `CoreDataHerdRepositoryContractTests`, `CoreDataAnimalRepositoryContractTests`, other M4–M8 feature contracts, and the M0 identity contracts own repository create/update/delete, duplicate-write rejection, revision, business validation, and UI-facing projections. M10 owns startup/Herd bootstrap and recovery. The M12 physical delete-rule contract owns cascade/nullify relationships. No duplicate per-feature suites are added here.
- **Constraints:** The running application supports one selected local Herd and rejects ambiguous root states during bootstrap. Multiple Herds here are deliberately constructed **foundation-level corruption/isolation fixtures**, not a multi-Herd product feature. This work does not add unique-constraint migrations, alter persisted user files or schema, change production runtime, permit a second active Herd, add SwiftData imports/migration, or retire the cutover playbook. Legacy SwiftData upgrade/release handling is separately unresolved.
- **Verification:** Per `AGENTS.md`, static code review only unless the user explicitly requests running verification. Test existence does not imply test execution.
