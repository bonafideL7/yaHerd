# Milestone 10 Core Data Runtime Cutover Matrix

Milestone 10 owns the decisive production composition switch from the legacy SwiftData runtime to the Core Data implementations completed in Milestones 3–9. The app must remain single-stack at runtime: preparatory API adaptations may land before the final switch, but no production feature may read from one persistence system and write to the other.

## Ownership

- **This milestone:** production Core Data bootstrap, current-Herd scope wiring, `AppDependencies` composition, feature dependency cutover, required production port/caller adaptation, recovery-store composition, post-commit mutation publication, and proof that production dependency resolution no longer selects SwiftData.
- **Existing permanent contract owners:** Milestones 4–9 repository/read-model contracts own feature persistence semantics; `MutationBoundaryContract` owns successful-write publication ordering; Core Data foundation contracts own transaction rollback/store mechanics.
- **Milestone 11:** physical deletion of SwiftData models, repositories, container/bootstrap code, migration/repair code, and obsolete SwiftData-only diagnostics.
- **Milestone 12:** final architecture enforcement that rejects SwiftData/Core Data leakage into Domain/Presentation and prevents reintroduction of obsolete persistence architecture.
- **Out of scope:** migration of development SwiftData stores, dual-write/bridge/fallback architecture, CloudKit/share/sync behavior, Presentation redesign, and new product behavior unrelated to the persistence cutover.
