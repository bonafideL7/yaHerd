# Milestone 12 — bounded scoped read identity preflights and Pasture snapshot consistency

## Design before production edits

`CoreDataReadModelActor` currently repeats seven complete selected-Herd UUID integrity checks using one unbounded dictionary fetch plus one in-memory `Set` per entity. This scales peak transient memory with Herd size independently of Home's 1-template or Dashboard's 25-session output bound. Because all these scans implement the same invariant (reject any repeated persisted application UUID in the selected Herd), consolidate them into a private ID-only helper. Sort by persisted UUID and fetch at most 250 rows per request with `fetchLimit`/`fetchOffset`; compare each non-nil ID with the previous valid ID across batches. Equally sorted UUIDs are adjacent, so full-Herd duplicate detection requires constant retained ID state. Keep UUID/NSUUID bridging and nil-ID behavior identical. Cancellation is checked between pages. Do not weaken an identity check into a limited projected cohort or add a schema constraint, write path, migration or new persistence abstraction.

`fetchDashboardPastureRecords` independently invokes multiple Pasture, Group and per-Pasture active-animal queries in a fresh context but, unlike `fetchDashboardRecords`, does not pin `NSQueryGenerationToken.current`. Add the same generation pin immediately before Herd lookup so the standalone list cannot mix store generations across those queries. Do not change `dashboardPastureRecords` or N-per-Pasture count semantics in this PR; a grouped-count redesign requires independent verified performance and result-shape evaluation.
