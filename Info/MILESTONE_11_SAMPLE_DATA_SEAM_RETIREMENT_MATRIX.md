# Milestone 11 — Retire unreachable sample-data seeding seams

## Design, ownership, and safety

After merged PRs #139 and #143, the two SwiftData sample writers, their app adapter, and the original SwiftData model source are absent from the compiled app. `CoreDataAppPersistenceAssembly.makeDependencies` supplies `sampleDataSeeder: nil` to both durable and recovery runtimes, and there is **no Core Data implementation** of `SampleDataSeeding`. The remaining optional injection, empty-state sample buttons, mutation wrapper/reason, and Working reference refresh branch therefore cannot be reached by any assembled production path. Remove the entire now-dead dependency cluster rather than leaving callable stubs for an obsolete write architecture.

Keep actual `Add Animal`, inline entry, empty-state filters/show-inactive/show-archived, normal Core Data mutation and read projection behavior unchanged. Do not create a replacement sample writer. Retain `Info/SampleData` static text assets and `LegacySwiftData` archived original 19 Git blobs for historical reference; neither is production input. Do not touch Core Data store/entity definition, first-open legacy preflight, read-only recovery/export, persistent UUIDs, Herd selection, or SwiftData user files. Existing-user SwiftData-to-Core Data record conversion **remains an independent release blocker**. #139 owned legacy writer retirement; M4–M10 own current Core Data runtime, projections, transactions and durable identity; this PR owns removal of uncallable presentation/injection/mutation protocol seams only.
