## Dependency audit and boundaries

- Delete `ModelContainerFactory.swift`: all runtime clients were retired in earlier M11 PRs. Its remaining direct client is the unused test-only `TestSupport` schema/container fixture.
- Delete `YaHerdMigrationPlan.swift`: after removing the factory and dormant test fixture, no executable code consumes the plan. Retain `YaHerdSchemaV1`, existing model aliases and remaining legacy model declarations until their complete dependency graph can be removed in a separate M11 slice.
- Delete `FieldCheckHistoricalSnapshotMigrator.swift`: no active caller remains after the M10 Core Data cutover; M7 owns historical snapshots in the live Core Data implementation.
- Edit `yaHerdTests/TestSupport.swift` only to remove unused legacy fixture methods and the SwiftData import. Preserve the permanent asynchronous throw-assertion helper and its call sites.
- Adjust the stale migration-plan comment in `YaHerdSchemaV1.swift` so retained legacy type declarations do not cite a deleted implementation.
- Retain `CoreDataLegacyStorePreflight`, `RecoveryModeController`, all original SQLite/store file names, sidecars and archive/export behavior. **No legacy-to-Core Data record import exists. Existing-user upgrade shipping remains blocked until a separately approved data-preserving path is implemented.**
- No builds, tests, lint, verification scripts or manually dispatched CI runs are authorized by the current request and `AGENTS.md`.
