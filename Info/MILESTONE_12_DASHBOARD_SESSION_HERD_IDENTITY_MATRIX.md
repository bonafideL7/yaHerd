# Milestone 12 — Dashboard complete-Herd Working-session UUID preflight

## Design before production edit

The direct `CoreDataWorkingRepository.fetchSessions()` loads all selected-Herd `CDWorkingSession` rows and checks application UUID uniqueness before projecting the Working library. The independent `CoreDataReadModelActor.fetchDashboardRecords()`, consumed by `LoadDashboardUseCase` and `LoadHomeUseCase`, fetches **only the latest 25 active sessions** and validates uniqueness only in that limited slice. One active session can therefore have the same application UUID as a persisted finished/cancelled session or an off-page active session and still appear healthy on Dashboard/Home, contradicting the direct Working library.

**Design:** Inside the Dashboard's existing private read context, pin `.current` Core Data query generation before obtaining the Herd, then preflight **all selected-Herd Working-session UUIDs across every lifecycle status** using an ID-only dictionary-result request without fetch limit. If a persisted UUID appears twice in the selected Herd, throw the established `CoreDataPersistenceError.duplicateApplicationID` before projecting any Dashboard snapshot. Preserve the 25-active-session fetch, date-descending/UUID-ascending ordering, queue ownership/identity validations, Animal/Pasture Dashboard projections, Home consumers and all Core Data mutations. This is read-only and adds an O(selected-Herd session count) lightweight identity query per full Dashboard/Home snapshot; performance is not benchmarked.

**Ownership:** This PR owns the independent bounded Dashboard/Home Working-session UUID preflight and one-generation read consistency. The existing direct Working `fetchSessions` and its complete-list identity contract own full direct-library validation. M8 owns Working session start, finish, cancel, reopen, deletion, historical queue snapshots and transactional rollback. M9 owns the Dashboard/Home query architecture, 25-session bound, sorting and UI. M12 #166 and the Dashboard queue identity matrix own queue-item identity; this change does not fetch or validate off-page queue-item identities. No schema, repair, new state, SwiftData, sync or navigation.
