# Milestone 11 — Orphaned SwiftData Mapper Removal Matrix

After merged PR #129, the active Core Data runtime does not invoke the original Animal or Pasture mapper types. This PR removes only orphaned SwiftData mappings and the legacy Herd overload. It does not touch test-dependent Dashboard/Field Check/Working mapping or old user database files.

## Reference and ownership inventory

- **Delete:** `yaHerd/Data/Mappers/AnimalMapper.swift` and `yaHerd/Data/Mappers/PastureMapper.swift`. Repository search finds no remaining Swift call sites; only stale architecture document references survive and will be reconciled in the final M12 architecture update.
- **Modify:** `yaHerd/Data/Mappers/HerdMapper.swift` by removing only the outgoing `extension Herd { toSummary() }`; retain `extension CDHerd` unchanged because `CoreDataHerdRepository` calls that overload for read and rename.
- **Retain:** `DashboardMapper.swift` (used by `DashboardMapperTests`), `FieldCheckMapper.swift` (Core Data extension plus `FieldCheckMapperNeedsAttentionTests`) and `WorkingMapper.swift` (Core Data extension). Those require later separate test/model ownership.
- **Retain:** all Core Data repository/read implementations and their permanent behavior contract owners (M3–M9), all legacy SwiftData models/schema/test fixtures, and recovery/export.
- **Release safety:** legacy SwiftData records still are **not imported into Core Data**. Original SQLite files and sidecars must be preserved for recovery/export pending an explicit upgrade/migration decision.
- **Build:** Xcode uses filesystem-synchronized source groups; source deletion removes the two unused mappers from the app target without manual project membership changes.
