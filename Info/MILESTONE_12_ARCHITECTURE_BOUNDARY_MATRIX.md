# Milestone 12 — Architecture Boundary Enforcement Matrix

## Design and affected production surface

This first Milestone 12 slice extends the existing `Scripts/verify-architecture.sh`; it does not introduce another verifier or modify app runtime behavior. Static review of `yaHerd/` shows that the active Core Data store and managed models live in `Data/`, production assembly and preflight live in `App/Persistence/`, and the sole existing App exception is `App/Recovery/RecoveryModeController.swift`, which performs a read-only Core Data store probe. Presentation receives Domain snapshots and feature-scoped dependencies, and Domain has a Foundation-only import policy. The frozen `LegacySwiftData/` archive remains outside app and test compilation under the existing Milestone 11 pin/target-membership guard.

**Invariants:** No persistence-native Core Data import or managed-object/context/store usage in Domain or Presentation. Non-persistence App code must not directly use Core Data framework types; the existing recovery probe is an explicit, narrowly scoped integration exception. Production cannot reintroduce SwiftData or cloud/shared-store/sync primitives through SwiftUI accessors, imported modules, unapproved packages, or Xcode capabilities; Xcode entitlement declarations cannot enable iCloud persistence. Existing Core Data repositories, identity/transaction behavior, local recovery and exports, and all production read projections remain unchanged.

## Ownership and limitations

- **Owned in this PR:** static architecture enforcement (including SwiftUI Core Data accessors and fail-closed production imports/package products) in the existing verifier, and this behavioral matrix. Changes do not alter store model, mappers, repositories, Presentation, dependency assembly, recovery implementation, tests, or user data.
- **Delegated:** M0/M4–M9 permanent Core Data behavioral and identity contracts; M10 selected-Herd boot, local persistent store and recovery; M11 frozen historical schema integrity. Later M12 PRs own remaining Core Data integration gaps and final `Info/ARCHITECTURE.md` cleanup/deletion of `Info/CORE_DATA_CUTOVER.md`.
- **Release blocker:** legacy SwiftData user records are not converted by the running app. This guard must not be used as evidence that an upgrade importing those records is available.
- **Verification:** not run by user instruction under `AGENTS.md`. Self-review consists of inspection of verifier rules against the current production source and project, plus an examination of the final diff and matrix.
