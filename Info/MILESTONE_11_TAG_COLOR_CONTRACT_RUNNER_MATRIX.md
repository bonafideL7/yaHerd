# Milestone 11 — Core Data Tag Color Contract Runner

PR #130 removed orphaned SwiftData mapper code. Tag Color is **not** yet safe to delete: `TagColorRepositoryContract` exists but its full permanent assertions have no live Core Data runner, while `TagColorLibraryStoreTests` still instantiates `SwiftDataTagColorRepository`.

Before modifying test code, this matrix records a scoped first stage: execute the **seven repository-only** and **two selected-Herd** assertions using a real in-memory Core Data repository and explicit Herd selection. Three permanent reference-heavy assertions cover four persisted-reference production behaviors (custom/custom collision remap, built-in collision remap, referenced custom removal, and hidden-color lookup for active and historical tags). A fifth distinct user-facing operation is tag editing or promotion after a hidden-color lookup; that workflow can persist an unintended fallback UUID and requires its own integration contract. None runs in this PR: they require real CDAnimalTag, Field Check, and Working reference probes in a subsequent M11 PR. No fake reference mutation, legacy test deletion, new production persistence, or data migration is in scope.

## Safety and ownership

- **Retain:** `SwiftDataTagColorRepository.swift`, `TagColorLibraryStoreTests.swift`, `TagColorLibraryHistoricalLookupTests.swift`, all original SwiftData schemas/model test fixtures, `CoreDataLegacyStorePreflight`, and recovery/export.
- **No upgrade conversion:** existing SwiftData records have no automatic import path into Core Data. Source-only unit tests do not alter the SQLite main files/journals and are not release approval.
- **Core Data setup:** a new `CoreDataTagColorRepositoryContractTests` test class uses `CoreDataPersistenceAssembly.inMemory()`, a real CDHerd and `CoreDataTagColorRepository(selection:assembly:)`, plus an unscoped physical CDHerd row-count control.
- **Deferred transaction coverage:** this runner does **not** inject a save failure after a Tag Color insert, update, delete, reorder, restore-defaults, or identity merge has been staged. A future M11 Core Data Tag Color transaction fault-injection contract must assert durable rollback, unchanged unrelated and referenced records, and same-context usability after failure. Invalid input, unknown UUIDs, and missing/stale Herd selection are not substitutes for that test.
- **Deferred production reference paths:** custom/custom normalized-name collision, custom/built-in collision, referenced custom hide/delete, and hidden-definition lookup for **active and historical Animal/dam tags** belong to a future **M11 Core Data Tag Color persisted-reference fixture and active-projection integration contract**, executing three permanent reference assertions against real CDAnimalTag, Field Check and Working records. The owner must inventory and verify `TagColorLibraryStore` resolution throughout Animal list/search, Dashboard rows, Pasture residents, Animal detail/tag-management, parent/dam and pregnancy sire selection, Field Check animal picker/check/finding views, and Working collection/search/sessions, not merely retired/history screens. **Distinct editor/promotion risk:** `AnimalTagEditView` resolves `colorID` on appear/save and `PendingAnimalTagManagementSection` resolves it on primary-tag promotion; a follow-up **M11 active-tag editor/promotion integration contract** must demonstrate that failed hidden-color lookup cannot silently save White/default in place of the original referenced UUID. Existing stub-based `TagColorLibraryHistoricalLookupTests` do not verify any of these Core Data paths. No `TagColorReferenceTestControl` callback in this PR supplies a physical reference; each deliberately throws.
- **Deferred retirement:** do not remove `SwiftDataTagColorRepository` or legacy Tag Color tests until the real reference and transaction-fault cases are addressed. Keep remaining M11 Working tests/repositories and all original data untouched.
- **AGENTS.md:** no build, test, lint, or manual CI trigger without explicit request; observe only automatic PR verification after opening.
