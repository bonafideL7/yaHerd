# Milestone 11 — Core Data Tag Color Contract Runner

PR #130 removed orphaned SwiftData mapper code. Tag Color is **not** yet safe to delete: `TagColorRepositoryContract` exists but its full permanent assertions have no live Core Data runner, while `TagColorLibraryStoreTests` still instantiates `SwiftDataTagColorRepository`.

Before modifying test code, this matrix records a scoped first stage: execute the **seven repository-only** and **two selected-Herd** assertions using a real in-memory Core Data repository and explicit Herd selection. The three reference-heavy assertions require actual CDAnimalTag, Field Check, and Working reference probes and remain for a separate M11 PR. No fake reference mutation, legacy test deletion, new production persistence, or data migration is in scope.

## Safety and ownership

- **Retain:** `SwiftDataTagColorRepository.swift`, `TagColorLibraryStoreTests.swift`, `TagColorLibraryHistoricalLookupTests.swift`, all original SwiftData schemas/model test fixtures, `CoreDataLegacyStorePreflight`, and recovery/export.
- **No upgrade conversion:** existing SwiftData records have no automatic import path into Core Data. Source-only unit tests do not alter the SQLite main files/journals and are not release approval.
- **Core Data setup:** a new `CoreDataTagColorRepositoryContractTests` test class uses `CoreDataPersistenceAssembly.inMemory()`, a real CDHerd and `CoreDataTagColorRepository(selection:assembly:)`, plus an unscoped physical CDHerd row-count control.
- **Deferred:** real reference-remap/history control and eventual SwiftData Tag Color repository/test removal. Keep remaining M11 Working tests/repositories and all original data untouched.
- **AGENTS.md:** no build, test, lint, or manual CI trigger without explicit request; observe only automatic PR verification after opening.
