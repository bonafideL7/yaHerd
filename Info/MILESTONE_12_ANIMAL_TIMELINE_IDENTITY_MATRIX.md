# Milestone 12 — Animal timeline projection identity matrix

## Design and ownership

The Core Data Animal timeline currently constructs `AnimalTimelineEvent` with its default `UUID()` for every projection. A second read of unchanged Core Data state therefore returns different row identities, even though sorting already uses stable persisted source IDs. `AnimalTimelineView` independently builds `DayGroup` with `UUID()` every time its view-local computed grouping recomputes. This is a derived read-model/UI identity bug, not a need for new persisted identifiers.

**Design:** Derive the timeline event's opaque `String` identity from its persisted source UUID plus its **event discriminator**. Explicitly distinguish primary birth, offspring birth, health, pregnancy, movement, status, tag assignment, and tag retirement; independent entity types may legally reuse a UUID. Make the event initializer require its stable identity rather than silently mint a new UUID. Give a day group its already-normalized calendar-start `Date` as identity. Event content, timestamps, event ordering, and Core Data rows remain untouched.

**Contract owner:** This PR owns derived Animal timeline and calendar-group identity; the existing Animal repository and read-model contracts own underlying movement, health, pregnancy, status and tag historical data, archive state, and live Pasture rename fan-out. M8/M9 remain owners of Field Check, Working, Dashboard and Home behavior. M10 owns store recovery. No SwiftData, schema, migration, or persistence write changes.
