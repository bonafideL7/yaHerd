# Milestone 12 — Dashboard complete-Herd Working queue UUID identity

## Design before production editing

`CoreDataReadModelActor.fetchDashboardRecords()` independently supplies `LoadDashboardUseCase.execute` and `LoadHomeUseCase.execute`. It validates all selected-Herd Working session UUIDs but validates Working queue UUIDs only among the first 25 active session summaries. The direct `CoreDataWorkingRepository.fetchSessions`, `fetchSessionDetail`, and `fetchQueueItemEditor` preflight the complete selected-Herd `CDWorkingQueueItem` cohort. A queue in a visible active session can share its UUID with a queue in a finished or 26th active session: Home/Dashboard will emit a summary that the direct Working library refuses to address. This is a distinct completed/off-page identity boundary not solved by #171's displayed active-session cohort check.

Within Dashboard's existing read-only, query-generation-pinned `context.perform`, preflight **all** selected-Herd Working queue UUIDs using ID-only dictionary fetches scoped to `herd == %@`. Reuse the existing typed `CoreDataPersistenceError.duplicateApplicationID`. Keep the 25 active-session display bound, sorting, session/Herd relationship checks, derived counts, and independently selected Herd behavior unchanged. Replace the now-redundant combined displayed-session UUID validator; per-session graph ownership validation stays with `dashboardWorkingSessionRecord`. Do not add queue hydration for every session, change writes, new abstractions, Core Data schema, legacy SwiftData, migration, UI, navigation, recovery or cloud/sync.

**Owner:** This PR owns the independent Dashboard/Home complete selected-Herd queue UUID preflight and its permanent SQLite regression. #166 owns direct Working full-Herd queue identity and direct list/detail/editor. #171 owned Dashboard's narrower displayed-session reconciliation (superseded only in scope by this PR). M8 owns Working session/queue lifecycle, snapshots, writes and relationship validation. M9 owns Dashboard/Home query shape, 25-row active-session window and presentation. M10 owns app injection. Original SwiftData data-preservation/upgrade release decision remains separate and unresolved. ID-only full-Herd scans incur additional O(queue rows in selected Herd) read work; execution and performance are unverified under AGENTS.md.
