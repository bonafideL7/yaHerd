# Milestone 11 — Physical Tag Color Reference Contract Matrix

This focused follow-on to merged PR #131 wires the remaining **three persistence-neutral Tag Color reference assertions** to the existing Core Data runner with a real, test-only managed-object reference graph. The three invariants are materially distinct: custom-to-custom UUID remap, custom-to-built-in UUID remap, and hide/delete that retains historical reference identity.

## Boundary

- **In scope:** a real `TagColorReferenceTestControl` that creates `CDTagColorDefinition` and a current and retired `CDAnimalTag` owned by `CDAnimal`, `CDFieldCheckSession`/check/finding snapshots, and `CDWorkingSession`/queue item snapshots. Query the **seven real physical reference fields through a fresh Core Data context** after each operation. Run the three existing M0 assertions, plus actual `TagColorLibraryStore` hidden-definition lookup on a current Animal color ID.
- **Not in scope:** production UI/tag editor fixes, injected failed-save transaction tests, SwiftData repository/test/model removal, persisted legacy user-data upgrade. These have concrete subsequent M11 owners documented below.
- **Safety:** preserve `CoreDataLegacyStorePreflight` and recovery/export; all fixture data is in `CoreDataPersistenceAssembly.inMemory()`, never a device or old-user SQLite file.

## Non-removal gate

Even with all twelve existing `TagColorRepositoryContract` assertions invoked against Core Data, SwiftData retirement is **not** complete until reference-aware UI projections, fallback-safe `AnimalTagEditView`/pending-tag promotion and transaction save-failure rollback are separately covered. Legacy user data still lacks an automatic SwiftData-to-Core Data migration. No M11 cleanup may silently erase or make inaccessible the sole original store.

## Execution and deferred guarantees

The Core Data contract runner now invokes all three reference-dependent M0 assertions and one real-store hidden-definition test. Automatic pull-request verification, not manually launched test execution, determines whether these tests pass. A separate M11 integration work item retains full active Animal list/editor, parent/pregnancy, Dashboard/Pasture, Field Check and Working UI behavior. A transaction fault-injection work item still owns post-stage save failures, rollback and same-context recovery. An additional unrelated-Herd/reference control is not asserted by this focused fixture. SwiftData user data and original SQLite/sidecar recovery remain unchanged.
