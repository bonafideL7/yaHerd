# Milestone 12 — Direct Pasture / Group Selected-Herd UUID Identity

## Design recorded before production edits

Direct Pasture and Pasture Group *single-ID* reads already use `CoreDataLookup.herdOwned`, which rejects two physical rows with the same UUID inside one Herd. In contrast, the complete selected-Herd `CoreDataPastureRepository.fetchPastures(herd:in:)` and `fetchGroups(herd:in:)` collection helpers return rows without checking persisted UUID uniqueness. Lists and selection options can expose duplicated application identity, `validatePasture*IDsExist` turns corrupted collections into a `Set`, `reorder` uses `Dictionary(uniqueKeysWithValues:)` (which can trap), and `deleteGroups` iterates matching IDs. Related detail/summary projections can also show ambiguous linked/group-member identities.

Reuse the existing `CoreDataAnimalMutation.validateUniqueApplicationIDs` helper on the **complete selected-Herd physical Pasture/Group cohort**, at the existing shared fetch boundaries, before any ID mapping or mutation. Validate the related cohort when projecting links/member counts. Keep direct targeted `herdOwned` lookups unchanged. Fail closed with existing `CoreDataPersistenceError.duplicateApplicationID`; no row selection, deduplication, UUID remint, physical schema constraint, repair, rekey, or write. UUID reuse in a different Herd remains legal. Preserve all ordering, ownership/relationship validation, transactions, navigation, read-model actors, UI, and historical data.

**Contract ownership:** this PR owns only scoped direct Pasture and Group cohort/read-identity enforcement plus permanent file-backed regressions in the existing `CoreDataAnimalRepositoryContractTests` suite. M4/M6 own healthy CRUD/reorder/group assignment/Pasture deletion and transactions. PR #161 owns foreign-Herd Pasture/Group read-graph relationships. Previous M12 Pasture read-order PR owns sort precedence and ties. M9 owns independent async Dashboard/Animal-list queries. The existing generic `CoreDataLookup` and M12 SQLite contracts own single-ID ambiguity and read-only reopening; no new runner or abstraction is needed.
