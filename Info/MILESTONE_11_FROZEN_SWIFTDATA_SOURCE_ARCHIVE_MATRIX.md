# Milestone 11 — Move frozen SwiftData source outside the production source root

## Design and scope

PR #142 excluded all 19 pinned legacy SwiftData source files from the filesystem-synchronized `yaHerd` app target but left their byte-identical definitions under `yaHerd/Data`. This continuation removes the **source-tree** dependency without deleting the only retained historical schema. Move the exact 19 Git blobs to a repository-root `LegacySwiftData/Data/...` archive, leaving contents and relative Data paths unchanged. The archive is **not** an Xcode source root or test target, and must not become a runtime import/migration dependency.

The existing Git blob fingerprint manifest remains authoritative and is relocated to the archived paths. The production Swift source ban becomes unconditional: no SwiftData import, SwiftData macro/runtime API, or original schema reference anywhere in `yaHerd`. Reject both missing/modified archived blobs and unexpected archived `.swift` files. Keep the existing attached-Xcode-exception aggregate guard but reduce its exact permitted app exclusions to `Info.plist`, because archived SwiftData files no longer reside under `yaHerd`. Do not remove or relax the app synchronized-root/target checks, the independent Domain/CloudKit checks, or the historical store safeguards.

**Explicit limit:** archive is source retention, **not data migration**. M10 `CoreDataLegacyStorePreflight`, read-only recovery and TAR export remain unchanged; existing SwiftData user records are not made accessible through Core Data. No existing-user upgrade may ship as lossless until a separately approved conversion/import or data-preserving release path exists. Do not edit existing user's storage files, local Core Data schema, runtime repositories, feature APIs or test target. Tests/build/verification are not manually executed without an explicit user request under `AGENTS.md`.

## Static review checklist

- Verify 19 source blobs retain exactly their earlier Git SHA-1 pins and unique `LegacySwiftData/Data/...` paths.
- Inspect all Xcode source-root/exception references; the app permits only `Info.plist` and the test root remains untouched.
- Trace the Core Data-only runtime, recovery and read projection paths for any reliance on archived symbols; none may remain after PR #142.
- Confirm the production ban has no SwiftData allowlist and the archive remains checked for both modifications and unrecognized additions.
- Keep the explicit **existing-user data import/release blocker** open; moving archival source does not make past user data accessible.
- Verification remains **not run by user instruction**, regardless of automatic CI that GitHub may trigger for a PR.
