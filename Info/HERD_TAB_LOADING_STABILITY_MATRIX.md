# Herd tab navigation stability — behavioral coverage matrix

## Design and production call graph

- `MainTabView` owns one `TabView` with Home, optional Dashboard, YaHerd and Search. The current conditional `yaherdTabViewBottomAccessory` helper alternates between two view *types* as selection changes. The fix permanently applies Apple's `tabViewBottomAccessory(isEnabled:content:)` modifier, so only the accessory's enabled state changes. Keep `AppNavigationPresentationModifier`, the router, Search's `role: .search`, and the native expanded/inline accessory unchanged.
- `HerdTabRootView(.herd/.search)` constructs `HerdView`. It switches between `AnimalListView` and `PastureTileListView`, discarding their `@State` view models when the mode changes. Move ownership of each `@Observable` list model to `HerdView`'s `@State` and inject into the active child. Herd and Search each retain **separate** animal models: sharing one would race the independently derived search/filter/sort requests. The standalone `#Preview AnimalListView()` still constructs its own default model.
- `AnimalListView.task → AnimalListViewModel.observe → AnimalListSnapshotReading.fetchAnimalSummarySnapshot + AnimalListQueryReading.fetchAnimalPastureOptions → AnimalListDerivationActor` loads in two asynchronous stages. Until the first valid derivation, the current UI wrongly treats an empty derived array as truly empty. Separate *initial loading*, *initial fetch error*, *ready with zero matches*, and *ready with animals*. Keep the last valid derived view while a loaded model revalidates after mutations.
- `PastureTileListView.task → PastureTileListViewModel.observe → PastureListReader.fetchPastures` reads synchronously after the first body render and currently displays the "no pastures" view while uninitialized. Expose a loaded/error state and reserve the same content region with a stable loading or retry view before showing actual empty/grid/filter results.
- Existing `ApplicationMutationStreaming` revision cursors own refresh, existing Core Data actors/repositories own snapshot correctness, and `AnimalListDerivationActor` owns filtering/sorting. No new global cache, Core Data write, SwiftData code, or navigation ownership is introduced.

## Verification & ownership

- This PR owns TabView structural stability, Herd-owned model lifetime, and correct *initial* Animals/Pastures loading/error presentation. Existing actors/repositories and their contracts own persistence, cancellation, mutation revisions, section derivation and sorting.
- No other PR claims these changes. Do not share an AnimalListViewModel instance between Herd and Search, or move read-model state into AppNavigationState.
- Source-review checks: navigate Home↔Dashboard without alteration; Home/Dashboard↔Herd Animals and Herd Pastures; Herd Animals↔Search; Herd Animals↔Pastures repeatedly; iOS expanded/inline bottom accessory; no phantom empty-herd/seed UI before load; retry after initial read failure; retain rows through mutation refresh failures; returning to a hidden mode after a revision fetches latest data.
- iOS runtime/appearance, CI, build, and tests are **not executed** per `AGENTS.md` without user authorization.
