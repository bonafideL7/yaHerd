# Milestone 11 — Freeze the Legacy Persistence Boundary

## Design and scope

The M10 cutover runs the whole app on Core Data, and M11 PRs #127–#140 removed the unused SwiftData runtime repositories, assemblies, mappers and extensions. The remaining archived SwiftData model declarations, `YaHerdSchemaV1`, its aliases and treatment vocabulary are retained pending an explicit existing-user lossless upgrade decision. This is a **static architecture safeguard**: it does not convert legacy stores or delete model declarations.

Before editing verification code, inspected `yaHerdApp`, `CoreDataAppPersistenceAssembly`, `CoreDataLegacyStorePreflight`, the Core Data app-graph tests, `Scripts/verify-core-data.sh`, the surviving model/schema paths, and the existing architecture checker. The existing Core Data verifier only rejects `import SwiftData` in three specific Core Data directories; it cannot reject a newly added dependency in App/Presentation/other Data directories.

**This PR owns:** the repository-wide static SwiftData import/API, legacy direct-schema-reference and CloudKit regression guard in `Scripts/verify-architecture.sh`. **Other owners:** M10 Core Data graph/preflight/recovery, M4–M9 repository contracts, and a separate lossless existing-user conversion/release decision. No active repository, presentation behavior, schema, migration mechanism, tests, Xcode target settings, startup, or persisted data changes.

No verification, test, lint, build or CI command is run under `AGENTS.md` absent explicit user instruction.

## Static inspection and release boundary

- Legacy allowlist is **exact file paths** rather than `yaHerd/Data/Models/**` wildcard so a new file there cannot silently add another SwiftData entry point.
- New `SwiftData` or `CloudKit` imports anywhere else fail; legacy schema references outside frozen model/schema files fail; `@Model`, `@Query` and container APIs outside the frozen set fail. Source scanning is repository-wide and future-file-inclusive.
- Old `YaHerdSchemaV1`, `YaHerdCurrentModels`, `WorkingTreatmentTerminologyCompatibility`, preflight, recovery and archive/export remain in place. Existing users cannot yet be automatically upgraded from their old SwiftData files; this remains a release blocker.
- Self-review uses source/diff inspection only. The scripts are intentionally not executed in this conversation.
