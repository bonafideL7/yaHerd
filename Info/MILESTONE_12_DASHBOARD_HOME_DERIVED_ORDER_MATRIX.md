# Milestone 12 — deterministic Dashboard and Home derivation ordering

## Design and scope

The active local Core Data store returns distinct records by UUID, but sibling readers, contexts and dictionary/relationship projections do not promise iteration order. Dashboard/Home derivation currently sorts several user-facing collections only by display tag, name, timestamp, metric or count. Equal keys are common (notably untagged cattle and simultaneous Field Checks), so Dashboard lists, Home action rows, the highlighted active Working session and top-eight offspring metrics can shift on reload even when no records changed.

Preserve each current primary sort criterion and append **persisted application UUID ascending** as the final tie break. For offspring metrics, choose the first nonblank historical dam display tag from offspring in persisted offspring-UUID order, rather than using whichever record Core Data returned first. Avoid writing to stores, altering relationships, statuses or historical snapshots, and do not add a sorting infrastructure abstraction. This is read-only Domain derivation; the M5/M7/M8/M9/M12 SQLite/repository owners retain physical lifecycle and corruption contracts. No SwiftData migration or CloudKit work.
