# Milestone 12 — complete-Herd template identity before bounded Home suggestions

## Design before production edit

The direct treatment-template repository validates all selected-Herd `CDWorkingTreatmentTemplate.id` values before exposing the complete template library. Home's independently bounded `CoreDataReadModelActor.fetchHomeTreatmentTemplates(limit:)` checks only the returned first `limit` rows. With a healthy first template and two same-UUID physical templates later by name, Home silently projects valid suggestions even though the direct library correctly rejects an ambiguous selected-Herd store. This is a concrete read-projection disagreement, not a request to remove Home's bound.

**Implementation:** use a selected-Herd `NSFetchRequest<NSDictionary>` fetching **only `id`** to detect duplicate persisted template UUIDs before running the existing bounded, name-then-UUID-sorted `CDWorkingTreatmentTemplate` request. Keep existing `CoreDataPersistenceError.duplicateApplicationID`, no schema/repair, no new abstraction, no change to strict `WorkingMapper.treatmentTemplateItems` decoder. The integrity scan is O(template count) in lightweight IDs, and the Home mapped/materialized result remains bounded. Keep Home's existing selected-Herd scoping; do not expand to other Herds.

**Scope and ownership:** This PR owns Home's full selected-Herd template *identity* validation prior to the bounded suggestion read. M12 #162 owns direct complete-list template identity plus both readers' name/UUID order. M9 owns Home loading, suggestion limit, independent background actor architecture, and error presentation. M8 owns template edits, deletion, snapshots and Working session lifecycle. Earlier M12 strict treatment-template payload decoding remains unchanged. No SwiftData, CloudKit, sync, recovery-mode write, navigation, or UI change.
