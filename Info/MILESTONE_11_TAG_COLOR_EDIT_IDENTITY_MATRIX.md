# Milestone 11 — Preserve Existing Tag Color IDs on Tag Edit and Promotion

## Production tracing and design boundary

In the Core Data runtime, a removed-but-referenced custom Tag Color remains physically present with `isHidden=true`. The presentation library’s `resolvedColorID(_:) ` is intentionally a **display fallback**: if `definition(for:)` cannot read the explicit UUID (including transient read errors), it yields the default White or selected default UUID. That is correct for formatting unknown/absent colors, but **incorrect on write paths**: `AnimalTagEditView` uses the fallback in `.onAppear`, palette selection, and save; `PendingAnimalTagManagementSection.syncPrimaryTag` uses it to populate a pending primary draft.

Do not change the existing `resolvedColorID` contract globally because Animal list, Dashboard, Pasture, Field Check, Working and tag-formatting callers depend on display fallback semantics. Introduce a narrow selection method for editing: **existing nonnil application color ID is always retained, nil receives default**. Only an explicit palette tap can overwrite existing ID. If the definition cannot be read, display a warning in the tag editor that the saved ID will remain unchanged unless another color is selected.

The sibling `AddAnimalViewModel` conversion already preserves explicit IDs via `colorID ?? defaultTagColorID`; no change needed. `WorkingSessionAnimalWorkView.tagReplacementSheet` also embeds this editor but has a separate mutation and history boundary: `WorkingQueueItemEditorViewModel.replacePrimaryTag` retires the original primary, creates a new tag, and changes the Working queue's captured tag. This PR will cover that path in its existing permanent Core Data Working contract, including hidden-color UUID identity, reload and rejection without partial writes. Physical seven-category Core Data reference repair/hidden lookup is already implemented in merged PR #132, while transaction fault-injection and complete screen-by-screen active-projection coverage remain separate future M11 owners.

## Verification and data safety

- **Scope:** `TagColorLibraryStore` narrow write-identity helper, `AnimalTagEditView` editor/preview swatch handling, `PendingAnimalTagManagementSection` primary binding, the existing persistence-neutral `TagColorLibraryHistoricalLookupTests` for hidden/unavailable/unknown/nil selections, and the existing `WorkingRepositoryContract+PlansTagsAndTemplates`/Core Data runner for the real Working primary-tag replacement/history path. No new SwiftData infrastructure.
- **Retain:** existing presentation display fallback `resolvedColorID`, persisted Core Data repositories and contracts, all legacy user SQLite databases/journals, `CoreDataLegacyStorePreflight` and recovery/export.
- **Not yet proven:** UI-level automation for all active pickers/rows and forced save transaction rollback remain delegated to separate M11 integration/fault-injection work. App upgrade from legacy SwiftData user records remains blocked without a data-preserving conversion plan.
