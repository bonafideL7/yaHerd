# Milestone 12 — Prelaunch legacy SwiftData cutover retirement

## Scope and design (recorded before production edits)

The app has **not launched**. Owner decision (2026-10-15): **no existing user data to preserve; no legacy data import, conversion, migration, upgrade, archive or first-launch compatibility requirement**. The sole production persistent store is local Core Data. This decision supersedes earlier M10/M11 legacy preservation and release-gate policy; historical matrix documents are records of previous work, not active product requirements.

Production trace: \`yaHerdApp.bootstrap\` → \`CoreDataPersistentContainer.defaultStoreURL\` → \`CoreDataAppPersistenceAssembly.load\` → \`CoreDataLegacyStorePreflight.ensureSafeFirstOpen\` → \`CoreDataPersistenceAssembly.load\` → \`CoreDataAppHerdBootstrapper.resolveOrCreateCurrentHerdID\` → the same feature-scoped dependencies and Home/Dashboard/Animal/Pasture/Field Check/Working read models. The preflight blocks first launch based on obsolete SwiftData files and orphaned journals, despite the absence of any released legacy installation. \`RecoveryModeController.recoverableStoreFiles\` also enumerates those legacy paths and adds them to diagnostics and TAR exports. M11's \`LegacySwiftData\` folder contains a frozen 19-file schema solely for hypothetical upgrades; \`Scripts/verify-architecture.sh\` pins its exact Git blobs. These artifacts are now obsolete and create unwanted runtime, source and documentation coupling.

**Design:** remove the legacy first-open preflight type and its startup invocation; let the Core Data loader itself decide whether its configured SQLite store can open. Do **not** add a delete/reset/migration/import action, delete actual device files, change the Core Data model, change the native Core Data recovery policy or relax Core Data's normal persistence/UUID/transaction invariants. Limit recovery inventory/TAR export to the current Core Data SQLite file and its "-wal", "-shm", "-journal" sidecars. Remove frozen SwiftData source files and obsolete blob-pin checking while retaining the production SwiftData/cloud/bridge ban, explicit rejection of a reintroduced \`LegacySwiftData\` source root, and existing synchronized Xcode target membership checks. Replace obsolete preflight/legacy-export tests with Core Data startup, inventory, and probe behavior in the **existing** contract suite. Update active README, architectural guidance and cutover checklist; do not rewrite historical completed PR matrices. A separate M12 final contract audit still determines when to retire the temporary cutover checklist.

**Ownership:** This PR owns removal of prelaunch-only SwiftData first-open policy, legacy recovery inventory, frozen schema source/archive pin, and their obsolete tests/docs. M10 app assembly/store bootstrap contracts own durable open and in-memory fallback; M12 recovery probe contracts own native store non-mutation and export; M4–M9 feature read and transaction contracts own all live Core Data projections; M12 architecture guard owns the production ban on SwiftData/cloud dependencies. No other PR overlaps.
