# Milestone 12 — Durable Working Template Identity and Read Projection Matrix

## Design and ownership

Core Data Working session mapping already decodes persisted treatment-plan entries through `CoreDataWorkingTreatmentPlanItemPayload`, which **requires** each entry's application UUID. Two production template readers instead decode directly as `[WorkingTreatmentPlanItem]`; that Domain model intentionally supplies a fresh UUID when JSON omits `id`. A corrupt persisted template therefore escapes from Data as a fabricated identity and can differ between reads. The same defect affects `CoreDataWorkingTreatmentTemplateRepository.fetchTemplates/fetchTemplateDetail` and `CoreDataReadModelActor.fetchHomeTreatmentTemplates`.

Keep the existing strict persisted-plan decoder in `WorkingMapper` as the sole Core Data decoding boundary for both sessions and templates. Preserve the Domain model's legacy decoding for non-Core-Data consumers. A corrupt template is rejected with an identity-bearing mapping error; valid templates still project their original names, counts, dose data and immutable item UUIDs. No user data is repaired, migrated, replaced or rewritten by reading.

- **This PR:** strict persisted Working template decode and read-only SQLite reopen integration for template detail, template list and bounded Home projections.
- **M8 permanent owners:** template create/update validation, UUID generation, write transactions, deletions and healthy template lifecycle contracts; existing Working session plan decoding, queue/work treatment semantics and history remain unchanged.
- **M9 permanent owner:** Home projection limit, selected-Herd filtering, fresh-context visibility and other read-model semantics; this PR tests only the shared persisted template decoding boundary.
- **M10 permanent owner:** store-open and recovery policy; M12 #148–#151 own physical deletion, SQLite identity, rollback and recovery inspection.
- **Excluded:** new legacy SwiftData conversion paths, schema changes, UI changes, and new verification tooling.
