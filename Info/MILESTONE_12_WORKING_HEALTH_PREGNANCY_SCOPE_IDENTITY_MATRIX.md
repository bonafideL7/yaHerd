# Milestone 12 — Working Health/Pregnancy Scoped Record Identity

## Design recorded before production edits

The selected-Herd direct Working read preflight already rejects duplicate application UUIDs across the complete queue-item and treatment-record cohorts (M12 PRs #166 and #167). Per-session `validateSessionGraph` also rejects repeated health and pregnancy record UUIDs inside one Working session. **Material gap:** two distinct Working sessions can contain two physical `CDHealthRecord` or `CDPregnancyCheck` objects bearing the same UUID. Each session's graph passes, and the shared health/pregnancy source identities remain ambiguous across the Herd even as the Working editor projects observation/castration and pregnancy history.

Extend the **same single selected-Herd direct-read boundary**, not each session's mapper, to validate both full selected-Herd `CDHealthRecord` and `CDPregnancyCheck` cohorts using `CoreDataAnimalMutation.validateUniqueApplicationIDs`. These are shared Animal entities, so include standalone Animal health/pregnancy records when checking their Herd-wide identity scope, rather than examining only Working-linked rows. Fail closed with the existing typed `CoreDataPersistenceError.duplicateApplicationID`. Do not choose a first record, remint IDs, delete or repair rows, or add Core Data uniqueness constraints (cross-Herd UUID reuse is valid). No change to healthy read shape/order, read-model actor, mutation transactions, UI, navigation, schema, migrations, SwiftData, or cloud persistence.

**Contract ownership:** This PR owns the strengthened **direct Working read** preflight and a file-backed integration regression for both cohorts. M5 owns general Animal CRUD, health/pregnancy identity and Animal timeline projections; this PR does not duplicate their general read tests. M8 owns Work data replacement, intra-session graph integrity and transaction rollback. M12 #166/#167 own queue/treatment identity; M9 owns bounded Dashboard/Home reads; M3/M12 foundation owns read-only SQLite store behavior. Existing App forwarding exposes the new read failure to callers traced below. This guard is not a universal write gate, notably when an already-open editor skips a conditional detail read.
