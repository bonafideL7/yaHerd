# Accessible custom control contrast — behavioral coverage matrix

## Review context and design

The first version of PR #196 introduced the shared foreground modifier before this matrix was committed. The review identified that omission; this document inventories the existing implementation and affected production paths retrospectively, and serves as the current coverage record before further scope changes.

**Problem:** The app's asset accent is dark burgundy in Light Mode and pale green in Dark Mode. Fixed white on the Dark Mode accent has about **1.56:1** contrast; black on the same fill has about **13.43:1**. White can also be unreadable on bright status colors such as yellow.

**Smallest design:** Apply the shared `View.readableForeground(on:)` modifier only to text or symbols on **opaque solid color fills**, using resolved light/dark `UIColor` components and WCAG relative luminance to choose black or white. Both are compared mathematically; the better option on an opaque sRGB fill always reaches at least 4.5:1. Keep existing accent/status background palette, shapes, sizes, actions, and custom disabled/read-only gates. SwiftUI's native button styles and tinted glass/material backgrounds stay responsible for their own composited foregrounds.

**Boundaries:** Rendering, Pasture Checks overview layout, and context-appropriate accessory visibility only. No Core Data, mutation, synchronization, migration, concurrent read logic, field-check workflow state, route mutation, persistent state, or scene restoration changes. Recovery *presentation* changes, not recovery behavior. A system appearance switch causes a new body evaluation; no extra app state or persistence should be introduced. Alpha/composited glass backgrounds do **not** meet the opaque-color assumption. Unresolvable non-RGB colors use SwiftUI's `.primary` fallback instead of inventing a contrast ratio.

## Contract ownership / out-of-scope behavior

- **This PR owns:** color resolution and black/white selection for solid fills, all opaque badge/floating/control foregrounds changed in this PR, selected/unselected Pasture Checks filter rendering, readable summary-row labels, compact overview metrics and Animal Sort/Filter accessory visibility. The permanent color test owner is `yaHerdTests/AccessibleControlContrastTests.swift`, covering light/dark and representative status tints; `yaHerdTests/AppNavigationStateTests.swift` owns the accessory-visibility invariant.
- **Existing contracts own:** the Home read projections, Dashboard lifecycle aggregation, Animal and Pasture create navigation/actions, Field Check filter/session data, app Settings and recovery controller state. This PR does not change their domain/model or repository behavior and should not duplicate their persistence, identity, or restoration tests.
- **No sibling PR dependency:** The branch is based on `main`. No other in-flight change is required for runtime contrast selection.
- **Intentionally outside scope:** contrast of native glass/material controls over unknown composited imagery, native toolbar styles, app-wide typography, a complete audit of all pre-existing colors, and unused Home/Dashboard components beyond their changed foreground expression. Native Animal Sort/Filter **visibility** on pushed routes is in scope; sort/filter actions are unchanged. Any future runtime evidence of low-contrast native glass must be evaluated against an actual rendered background before changing it.

## Review / verification disposition

- **Static caller trace:** Home Summary, Field Work, Pasture Operations, Work Pen, Records Cleanup, Setup Suggestions; Dashboard lifecycle chart; Animal list and Pasture list floating Add; Field Check list filters and detail quick actions; Recovery Mode persistent banner; plus `MainTabView`/`AppNavigationState` foreground-route eligibility. Remaining unused definitions are inventoried separately above.
- **Read projection trace:** Home snapshot/count/alert summaries; Dashboard lifecycle metrics; Animal and Pasture list rows; Field Check session summaries and mode-filtered sections; recovery controller state. Color modifier consumes only each supplied background color and SwiftUI appearance environment; does not fetch data or mutate the projections.
- **Static invariants:** same colors for background fills, same action closures, disabled/read-only conditions, geometry, sorting/filter enum, accessibility text/selection traits, model identity and screen ownership. Existing nonopaque glass and material styling remain unchanged, except removal of the redundant Start glass button.
- **Coverage source:** `AccessibleControlContrastTests` asserts ratio ≥4.5:1 for accent and eight built-in status colors in Light/Dark; `AppNavigationStateTests` owns root versus pushed-route accessory visibility; production call-path review covers Field Check row/overview rendering and unchanged routes.
- **Not run by user instruction:** no Xcode build, tests, lint, architecture scripts, concurrency verification or CI dispatch. Pixel-level rendered contrast, color differentiation settings, increased-contrast accessibility appearance, selected/unselected buttons in situ and translucent overlays remain **unverified** until an iOS simulator/device review.
