# Milestone 5 — Core Data Animal Aggregate Coverage Matrix

This matrix is the implementation/review inventory for Milestone 5. It covers the Core Data Animal repository and the real Animal aggregate transaction boundary while the running app remains on SwiftData until Milestone 10.

## Ownership

### Owned by this milestone

- Core Data `AnimalRepository` implementation for Animal list/detail/timeline/parent/offspring reads and direct Animal mutations.
- Core Data `AnimalAggregateEditReading`.
- Core Data `AnimalAggregateTransactionWriting` create/update boundary.
- `AnimalTag` as the sole persisted tag source for the Core Data Animal implementation.
- Parent, pasture, status-reference, status-history, movement-history, health-record, pregnancy-check, archive-state, and hard-delete behavior exercised through the Animal repository.
- `editorRevision` creation/rotation for aggregate writes and direct Animal-owned mutation paths implemented in this milestone.
- Stale-editor and missing-aggregate rejection before aggregate mutation.
- One-context/one-save aggregate rollback through the asynchronous `CoreDataTransactionExecutor`, including deliberately injected post-staging failure coverage in the Core Data Animal contract runner.
- Aggregate create/update writes are serialized through one non-reentrant gate shared by every `CoreDataAnimalRepository` created from the same `CoreDataPersistenceAssembly`; UUID/revision preconditions and the final save therefore remain one exclusive commit decision despite MainActor reentrancy.

### Existing permanent contract owners reused

- `AnimalRepositoryContract`
- `AnimalRepositoryReadModelContract` for Animal-repository projections that exist in this milestone.
- `AnimalAggregateTransactionContract`
- `PersistenceTransactionPreconditionContract` for Animal revision/missing-aggregate preconditions.
- `PersistenceTransactionRollbackContract` for Animal aggregate rollback.
- `AnimalAggregateCrossFeatureRevisionContract` for revision invalidation ownership across feature boundaries.
- `IdentityContract`
- `MutationBoundaryContract`
- `Info/TRANSACTION_BOUNDARIES.md`
- `Info/CORE_DATA_MODEL_BLUEPRINT.md`

### Follow-up transaction-gate completion

- This follow-up converts `AnimalAggregateTransactionWriting` to the Milestone 3 asynchronous mutation pattern and routes aggregate create/update through `CoreDataTransactionExecutor`; no synchronous wait compatibility path is retained for this transaction port.
- The async transaction path must preserve the model's repository-enforced identity/revision semantics under overlapping calls. The Core Data runner owns a concurrent same-ID create/stale-update probe in addition to ordinary success/failure execution.
- The permanent Animal aggregate/precondition/rollback contracts are converted to await the same Domain transaction port rather than testing a parallel API.
- A Core Data Animal contract runner owns the target wiring and post-staging failure injection. Production failure injection is exposed only as the same internal `beforeSave` seam already used by the Core Data Herd repository and executor contracts.
- Runtime editor wiring remains Milestone 10; there is still no production caller of this transaction port on the current runtime.

### Delegated / owned elsewhere

- Runtime dependency cutover and editor wiring to the new aggregate transaction port: Milestone 10. The current SwiftData runtime is not modified and no SwiftData transaction adapter is added.
- Pasture deletion transaction and revision effects from that transaction: Milestone 6.
- Field Check writes that mutate Animal editor-owned state/revision: Milestone 7.
- Working writes that mutate Animal editor-owned state/revision: Milestone 8.
- Dashboard, Home, paged Animal-list query, search/filter, and other performance read models: Milestone 9. Milestone 5 only guarantees the persisted Animal graph those readers consume.
- Tag-color collision remap revision rotation remains owned by the already-merged Tag Color Core Data repository.
- App mutation publication for the unused aggregate writer is wired when runtime dependencies cut over; ordinary Animal repository publication remains owned by the existing mutation wrapper.
- Milestone 9 owns Core Data `AnimalListQueryReading` and `DashboardQueryReading`. The permanent aggregate contract is split so Milestone 5 executes aggregate persistence/current repository projections now, while M9-only query-projection assertions remain owned and executable in Milestone 9 rather than requiring temporary readers here.

## Matrix notes

- The running application remains SwiftData until Milestone 10. No SwiftData implementation, adapter, or dual-write path is added.
- Milestone 9 owns production Dashboard/Home/paged list query implementations. Milestone 5 must persist state correctly for those future readers but does not introduce early performance-query repositories.
- The Core Data Milestone 5 runner must not satisfy `AnimalAggregateTransactionContract` by adding temporary Dashboard/list readers. Permanent contract assertions that depend on those ports are separated from M5-owned aggregate persistence/current repository assertions and remain executable when Milestone 9 supplies the target readers.
- The Core Data M5 runner executes every M5-owned `AnimalAggregateTransactionContract` entry point: tagged/untagged create, complete update, active Pasture move, dam retag, same-status metadata replacement, all-tags-retired clear state, non-editor-owned-state preservation, and every invalid complete-tag state for create/update. Those entry points always verify M5 editor/Animal/Pasture/Working/health/history projections; Dashboard/paged-list assertions run only when M9 production readers are supplied.
- The permanent Animal contracts remain the declared behavioral owners. This follow-up owns wiring them to the Core Data Animal implementation and converting only the contract calls required by the async transaction port; it must not create duplicate review-specific suites.
- Shared transaction contracts expose feature-scoped Animal aggregate fixture/functions for M5 so the runner does not require placeholder Milestone 6 Pasture-deletion probes; combined cross-feature entry points may remain as composition helpers.
- `IdentityContract` keeps its all-entity default but accepts an explicit entity-kind subset so M5 executes `.animal` and `.animalTag` identity preservation/duplicate rejection without claiming ownership of the other 16 durable entity runners. Its seed operation is asynchronous so the `.animalTag` duplicate probe can use the real async aggregate repository; the duplicate attempt targets a different pre-seeded owner Animal and therefore reaches Herd-scoped `reconcileAggregateTags` identity enforcement instead of a test-control preflight.
- Verification is not run unless explicitly requested.
