# Milestone 5 — Core Data Animal Aggregate Coverage Matrix

This matrix is the implementation/review inventory for Milestone 5. It covers the Core Data Animal repository and the real Animal aggregate transaction boundary while the running app remains on SwiftData until Milestone 10.

## Ownership

### Owned by this milestone

- Core Data `AnimalRepository` implementation for Animal list/detail/timeline/parent/offspring reads and direct Animal mutations.
- Core Data `AnimalAggregateEditReading`.
- Core Data `AnimalAggregateTransactionWriting` create/update boundary.
- `AnimalTag` as the sole persisted tag source for the Core Data Animal implementation.
- Parent, pasture, status-reference, status-history, movement-history, health-record, pregnancy-check, archive-state, and hard-delete behavior exercised through the Animal repository.
- `editorRevision` creation/rotation for aggregate writes and direct Animal-owned mutation paths implemented in this milestone.
- Stale-editor and missing-aggregate rejection before aggregate mutation.
- One-context/one-save aggregate rollback implementation for thrown staging/save failures. Deliberately injected Core Data failure execution remains unverified because this branch does not add or modify test runners.

### Existing permanent contract owners reused

- `AnimalRepositoryContract`
- `AnimalRepositoryReadModelContract` for Animal-repository projections that exist in this milestone.
- `AnimalAggregateTransactionContract`
- `PersistenceTransactionPreconditionContract` for Animal revision/missing-aggregate preconditions.
- `PersistenceTransactionRollbackContract` for Animal aggregate rollback.
- `AnimalAggregateCrossFeatureRevisionContract` for revision invalidation ownership across feature boundaries.
- `IdentityContract`
- `MutationBoundaryContract`
- `Info/TRANSACTION_BOUNDARIES.md`
- `Info/CORE_DATA_MODEL_BLUEPRINT.md`

### Current architecture blocker

- Milestone 3 requires final Core Data feature transaction ports to become async and use the asynchronous transaction executor instead of synchronously waiting on a private Core Data context.
- The permanent Animal precondition/rollback contracts in `yaHerdTests/**` still invoke `AnimalAggregateTransactionWriting` synchronously.
- The standing branch instruction prohibits modifying `yaHerdTests/**`. Until that instruction is relaxed or the permanent contracts are updated by their owner, the aggregate transaction port cannot be finalized without either violating Milestone 3 architecture or breaking the existing test target. The synchronous implementation on this branch is therefore provisional and must not be treated as the completed Milestone 5 transaction gate.

### Delegated / owned elsewhere

- Runtime dependency cutover and editor wiring to the new aggregate transaction port: Milestone 10. The current SwiftData runtime is not modified and no SwiftData transaction adapter is added.
- Pasture deletion transaction and revision effects from that transaction: Milestone 6.
- Field Check writes that mutate Animal editor-owned state/revision: Milestone 7.
- Working writes that mutate Animal editor-owned state/revision: Milestone 8.
- Dashboard, Home, paged Animal-list query, search/filter, and other performance read models: Milestone 9. Milestone 5 only guarantees the persisted Animal graph those readers consume.
- Tag-color collision remap revision rotation remains owned by the already-merged Tag Color Core Data repository.
- App mutation publication for the unused aggregate writer is wired when runtime dependencies cut over; ordinary Animal repository publication remains owned by the existing mutation wrapper.
