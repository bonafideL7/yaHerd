# Milestone 12 — SQLite Transaction Rollback Durability Matrix

## Scope and existing owners

`CoreDataTransactionExecutor.performWrite` creates a fresh private Core Data write context, runs a supplied operation, invokes an optional pre-save hook, commits once when `hasChanges`, and rolls back on thrown operation/save errors. The permanent in-memory `CoreDataPersistenceFoundationTests` already test a thrown staging error and an actual missing-required-field save failure. This M12 slice audits the independent **durable SQLite reopen** boundary for materially mixed writes and verifies continued writes following a failed save. It adds physical integration assertions to that same permanent foundation suite; it does not introduce another executor, global verifier, test runner, production code path, model change, migration, or recovery mode.

The complete set of six direct production entry paths into this shared executor is `CoreDataHerdRepository.renameCurrentHerd`, `CoreDataAppHerdBootstrapper.createInitialHerd`, `CoreDataPastureDeletionTransactionWriter.deletePastures`, `CoreDataAnimalRepository.performAggregateWrite`, `CoreDataFieldCheckRepository.performWrite`, and `CoreDataWorkingRepository.performWrite`. The last four wrap this very executor; they **do not** bypass its commit/rollback boundary. Their additional validation, coordination/gates, feature mutations, historical snapshots, error translation and post-commit publishing remain owned by M4–M10. Other synchronous Core Data repository writers (including direct Pasture and Tag Color writes) own separate context/save paths and their own permanent contracts; those writers are not direct callers of `CoreDataTransactionExecutor.performWrite`. This PR does not claim to replace those contracts or prove actual disk-I/O faults. Legacy SwiftData data import/upgrade and `Info/CORE_DATA_CUTOVER.md` retirement remain unresolved decisions.

## Static review and verification

- Exercise real disk-backed SQLite through the production assembly; after failed writes, inspect an **independent read-only assembly**, not only sibling contexts. Check restored updates, preserved deleted rows, rejected inserted rows, ownership and untouched controls.
- For real save failure, force Core Data validation by leaving the required Herd name unset. Assert `saveFailed` specifically, then make a valid follow-up commit using the original writer and inspect it through a new read-only assembly.
- Reconcile the complete diff against these rows, all six traced direct production executor callers, the native managed-object model and existing M4–M10 feature contracts. The four nested async wrappers delegate to the **same** executor; separately implemented synchronous writers are not included as callers.
- **Not run by user instruction** (`AGENTS.md`): do not run builds, tests, lint, scripts or manually trigger CI. Test compilation and results remain unverified.
