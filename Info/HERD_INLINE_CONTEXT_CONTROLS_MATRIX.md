# Herd inline entry contextual attribute controls — behavioral matrix

## Production call paths and design

- `AnimalListView.herdList` builds `AnimalListContentList`. Tapping an animal row calls `beginInlineEditing` and an empty tap row calls `beginNewInlineEntry`. Both display the same `AnimalListInlineEntryRow` with **one** `TextField("Tag or name"/"Edit tag or name")`; no new name, tag, or notes fields are introduced.
- Before this change `AnimalListView.bottomOverlay` renders `AnimalListInlineEntryAccessoryBar` in `AnimalListBottomOverlay` only while inline entry is active. The existing bar owns Sex, Pasture, Birthdate, and Save controls and their accessibility labels and state-derived values. Move that **same bar** into the active row below the single text field and keep its buttons' underlying callbacks and bindings; do not add a second bar or a different entry flow.
- When the keyboard is dismissed interactively without ending an inline entry, the active row must allow tap-to-refocus on the helper line and on unoccupied/padded portions of its rounded editing surface, not only the top HStack. Attach a focus action to these non-action surfaces and keep the action buttons at the foreground of hit testing so a tap on Sex, Pasture, Birthdate, Save, or Details still invokes only its existing callback without a redundant focus/commit transition. This is the same focus-recovery path for both new and edited rows; no focus coordinator is introduced.
- `AnimalListView.presentInlineEntryPicker` calls `AnimalInlineEntryViewModel.prepareForPickerPresentation()` before showing one of the existing `AnimalListInlineEntryDialogs` confirmation dialogs. `AnimalListInlineEntryDialogs` returns focus via `requestInlineEntryFocus` after selection; the separate date sheet follows the same rules. No new dialog/state implementation.
- `AnimalInlineEntryViewModel.commit` keeps parsing via `AnimalInlineEntryParser`, preserving `CreateInlineAnimalUseCase` and `UpdateInlineAnimalUseCase` as the only writers. Return/Save, empty text disabling, new-row continuation, existing-animal completion, and focus-loss save remain unchanged.
- When inline entry is active, `AnimalListBottomOverlay` must reserve **no** old accessory area. The `AnimalListToolbarContent` **Select Animals** action is reachable during new or existing inline entry. Previously `toggleBatchMode` simply toggled `batchMode`, leaving an active new-entry draft in the list; `AnimalListBottomOverlay` checked `inlineEntryIsActive` first, suppressing the batch Move/select-all bar. On transition into batch mode, complete a nonblank inline draft through the existing `commitInlineEntry(startNewEntryAfterCreate: false)` path, or cancel a blank draft; block selection when the write fails and preserve editable input. After the transition the list must never render an inline entry and the bottom overlay must prioritize the batch bar. Leaving batch mode still clears selection without starting any draft. Existing search/filter floating toolbar and inactive-state bottom spacers keep their prior predicates.
- Visually, the active list row should read as one rounded expanded editing surface with a single horizontal tag/name field at the top, unchanged new-entry helper text, optional details icon, and the existing four compact contextual controls beneath. Use system-background adaptive colors for legibility; do not alter other animal row appearances.
- No new repository, view model, parser, settings, schema, or business-logic mutations; use existing inline commit/cancel functions at the batch-mode transition; iOS 26 SwiftUI public APIs only.

- Preserve exactly one tag/name `TextField` per active row, unchanged placeholder, submit label, parser, helper, focus request/cancel semantics, and details action.
- Inspect sex/pasture/date dialog callbacks and their `prepareForPickerPresentation` guard; verify no new repository implementation or write path. Leaving batch mode clears selections, and inline row remains hidden whenever batchMode is true. Inspect row non-action tap targets (helper text, between controls, trailing and lower padding) after keyboard swipe-dismissal, for both new and edit modes, and verify metadata/Save/Details buttons remain actionable without being intercepted by refocus.
