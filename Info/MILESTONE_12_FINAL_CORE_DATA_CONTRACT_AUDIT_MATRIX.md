# Milestone 12 — Final Core Data cutover contract audit and checklist closure

## Design and decision before documentation edits

The active yaHerd runtime already uses a single local Core Data \`NSPersistentContainer\`, and M11 removed compiled SwiftData. M12 subsequently added physical relationship/delete contracts, durable SQLite transaction rollback contracts, Herd-scoped application UUID read contracts, independent direct and Home/Dashboard graph integrity projections, native read-only recovery contracts, and architecture checks. The prelaunch owner decision in \`MILESTONE_12_PRELAUNCH_LEGACY_RETIREMENT_MATRIX.md\`, merged as #184, ended the last SwiftData-upgrade preservation gate. This audit reconciles the temporary \`CORE_DATA_CUTOVER.md\` checklist against the *actual source wiring and permanent suites*. It does not run tests, declare a verified device build, introduce a migration, or reopen previously delegated non-cutover feature requests.

**Source/caller inventory:** \`yaHerdApp.bootstrap\` → \`CoreDataPersistentContainer.defaultStoreURL\` → \`CoreDataAppPersistenceAssembly.load\` → \`CoreDataPersistenceAssembly.load\` → \`CoreDataAppHerdBootstrapper.resolveOrCreateCurrentHerdID\` → \`makeDependencies\` → five Domain-facing feature containers, native Core Data repositories and independent \`CoreDataReadModelActor\` query readers. Startup failure → \`inMemoryRecovery\` with \`AppDataAccessMode.recoveryReadOnly\`; \`RecoveryModeController\` diagnoses/exports the native SQLite store and probes it with \`.readOnly\`. The model/lookup/transaction/mapping and native feature graph live in \`yaHerd/Data\`; Presentation and Domain never receive Core Data-managed objects or store identities. No first-open SwiftData gate or frozen legacy schema remains.

**Permanent contract owners checked:**
- **Physical schema:** \`CoreDataModelStructureTests\` — exact entities, application UUID, Herd relationships, indexes, nullify/cascade deletion, snapshot optionality, absence of remote persistence baggage.
- **Foundation and durability:** \`CoreDataPersistenceFoundationTests\` — independent SQLite reopened UUID/Herd identity, duplicate root/child scoping, transactional rollback of mixed changes after throw or actual save failure, persisted no-write read-only mode, physical Pasture/Animal delete-rule outcomes and historical snapshot controls.
- **Features and write semantics:** \`CoreDataHerdRepositoryContractTests\`, \`CoreDataTagColorRepositoryContractTests\`, \`CoreDataAnimalRepositoryContractTests\`, \`CoreDataFieldCheckRepositoryContractTests\`, \`CoreDataWorkingRepositoryContractTests\` and the reusable \`RepositoryContracts\` suites; pasture deletion and working lifecycle transaction paths, full-Herd identity/snapshots, rollback, unaffected controls, and post-commit mutation publication are owned by the respective existing contracts.
- **Read projections:** M9 \`CoreDataReadModelActor\` and \`CoreDataHomeReadModelContractTests\`, Animal/Field Check/Working contract suites; M12 matrices from #147 through #183 cover distinct source-to-Dashboard/Home/read library read-path integrity, stable order and bounded complete-Herd identity preflight.
- **App/recovery:** \`CoreDataAppHerdBootstrapperTests\` — one live local Herd, selected scope, durable reopen, read-only in-memory recovery, unsupported store types, safe probe, diagnostic inventory, first launch despite obsolete local filenames after #184.
- **Architecture:** \`Scripts/verify-architecture.sh\` — Domain Foundation-only, Presentation no native persistence, App narrow Core Data boundary, production no SwiftData, CloudKit/shared/bridge/injected remote package, app/test source membership. Script executable bit is preserved by #184.

**This PR owns:** final audit/contract-to-checklist mapping, updates to implemented architecture and model-blueprint document pointers, removal of the redundant temporary cutover playbook. **Delegated:** all production mutation, projection and recovery behaviors stay with the above permanent contracts and already merged M4–M12 PRs; independent UI product-feature work is not a persistence cutover gate. **Excluded:** new production changes, schema changes, SwiftData compatibility, app releases, actual device validation, test/CI execution, and hypothetical unreleased data preservation.

## Cutover-gate reconciliation

- **One native store and no SwiftData runtime:** current App/Data composition and \`Scripts/verify-architecture.sh\` source policies.
- **UUID/Herd identity and history:** M0 persistent Domain behavior contracts, M3/M4 and M12 independent SQLite identity and native physical delete-rule suites.
- **Atomic multi-record writes and post-commit publication:** M5–M8 feature transactions, M3/M12 rollback suite, M10 mutation wrappers/contracts.
- **Mapper and read boundaries:** M9 read-model, M4–M8 feature repositories, M12 direct-reader and Home/Dashboard parity matrices.
- **Recovery:** M10 native in-memory read-only startup, M12 native read-only store probe, and M12 prelaunch removal of obsolete legacy artifact scans.
- **Clean architecture:** permanent \`ARCHITECTURE.md\`, model blueprint and architecture guard cover framework imports, native type leakage, CloudKit/shared sync, package/product import and compiled source membership.

The temporary \`CORE_DATA_CUTOVER.md\` is not a necessary end-state artifact and is removed. Historical M0–M12 coverage matrices and \`Core-Data-SwiftData-replacement-execution-plan.md\` remain as implementation history, not live duplicate architecture authorities. No pending SwiftData data-preservation or release-upgrade decision exists.
