# Remove Status Reference picker from Animal forms — behavioral coverage matrix

## Design and production call graph

- Screenshot identifies the "Status Reference" section and "Referenced Status" picker in `AnimalStatusEditorSection` (`AnimalFormFieldSections.swift`). It is displayed when `availableStatusReferences` is nonempty or `statusReferenceID` is non-nil.
- Both `AddAnimalView` (including Add Offspring via `AnimalDetailView`) and `AnimalDetailView.editingContent` instantiate `AnimalEditorSections`, which currently filters status options and forwards `draft.statusReferenceID` to `AnimalStatusEditorSection`. Remove *only* this picker/section/footer from the shared form. Eliminate unused view-only forwarding/filtering inputs, while keeping the status-dependent Sale Details and Death Details sections and their existing input fields.
- `AnimalFormViewModel.makeInput` and `AnimalEditorDraft` retain `statusReferenceID`; `AnimalDetailViewModel.beginEditingStatus` continues clearing it when transitioning to a new base status. Core Data relationships, custom-status definitions, revision/concurrency rules and `AnimalDetailStatusSection` read-only historical projection are outside this visual change and must remain untouched.
- `AnimalFormViewModel.loadSupportData` continues fetching options as part of `LoadAnimalEditorOptionsUseCase` for this PR; changing the repository and its supporting readers is unnecessary to remove a form control.
- No additional editor fields, persistence transaction, schema change, migration, new setting, or feature removals.
