# Remove Status Reference picker from Animal forms — behavioral coverage matrix

## Design and production call graph

- Screenshot identifies the "Status Reference" section and "Referenced Status" picker in `AnimalStatusEditorSection` (`AnimalFormFieldSections.swift`). It is displayed when `availableStatusReferences` is nonempty or `statusReferenceID` is non-nil.
- All three `AddAnimalView` entry points are affected: the app's `.addAnimal` sheet in `AppNavigationPresentations`, Add Offspring from `AnimalDetailView`, and Add Offspring from `FieldCheckAnimalDetailView` (only when its session is editable and a prepared offspring draft exists). In the Field Check caller, `AddAnimalView` receives an `onSave` callback that calls `FieldCheckAnimalDetailViewModel.addTrackedAnimalToSession` with `createdAnimal.id` and the current `sessionID`. Both `AddAnimalView` and `AnimalDetailView.editingContent` instantiate `AnimalEditorSections`, which previously filtered status options and forwarded `draft.statusReferenceID` to `AnimalStatusEditorSection`. Remove *only* this picker/section/footer from the shared form, including its Field Check offspring presentation. Eliminate unused view-only forwarding/filtering inputs, while keeping the status-dependent Sale Details and Death Details sections and their existing input fields.
- `AnimalFormViewModel.makeInput` and `AnimalEditorDraft` retain `statusReferenceID`; `AnimalDetailViewModel.beginEditingStatus` continues clearing it when transitioning to a new base status. Core Data relationships, custom-status definitions, revision/concurrency rules and `AnimalDetailStatusSection` read-only historical projection are outside this visual change and must remain untouched.
- `FieldCheckAnimalDetailView` opens its offspring sheet only while `isSessionEditable` and its prepared draft is available. `AddAnimalView.validateAndSave` first creates the child, retains that `AnimalDetailSnapshot` in `pendingCreatedAnimal`, then awaits the optional `onSave` callback. A successful Field Check callback adds the child to the roster through `FieldCheckAnimalDetailViewModel.addTrackedAnimalToSession` and `FieldCheckAnimalDetailRepository` and then dismisses the sheet; sheet `onDismiss` refreshes animal and session projections. When the session mutation throws (e.g. the session closes or is no longer editable), `AddAnimalView` keeps the sheet open, displays an error and retries the **same created animal** on the next Save rather than inserting a duplicate. The changed shared form only omits the reference picker and does not alter any of those pathways.
- `AnimalFormViewModel.loadSupportData` continues fetching options as part of `LoadAnimalEditorOptionsUseCase` for this PR; changing the repository and its supporting readers is unnecessary to remove a form control.
- No additional editor fields, persistence transaction, schema change, migration, new setting, or feature removals.
