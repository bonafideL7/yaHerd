# Milestone 12 — Home Field Check full-Herd session UUID identity

## Production trace and design (before editing code)

`LoadHomeUseCase.execute` starts an independent `HomeFieldCheckQueryReading.fetchHomeFieldCheckRecords()` operation; `HomeViewModel` consumes its derived warning cards and history indicator. The Core Data implementation reads only unfinished/warning `CDFieldCheckSession` rows and checks session UUIDs **after** that predicate. The direct `CoreDataFieldCheckRepository.fetchSessions()` and `fetchSessionDetail(id:)` reject ambiguous session IDs across **all** selected-Herd sessions. A warning session whose UUID also belongs to a completed, resolved, off-filter session can therefore appear in Home while the direct library cannot safely address that identity. Two completed sessions may also have a duplicate ID and be invisible to this independent Home read.

Within the existing, pinned read-generation context, check every selected-Herd `CDFieldCheckSession.id` via an ID-only dictionary-result fetch **before** the warning-session query. Reuse `CoreDataPersistenceError.duplicateApplicationID` and `CoreDataAnimalMutation.validateUniqueApplicationIDs` for the already-filtered warning cohort; do not add a new validator or materialize complete historical relationships. Preserve the warning predicate, `startedAt`/UUID ordering, unresolved finding count/one-finding preview, `hasHistory`, other Field Check graph validation and independently scoped Herds. The extra scan is O(selected-Herd session count) per Home Field Check load; latency is not measured.

**Contract ownership:** This PR owns the independent Home complete-Herd Field Check session-ID preflight and its durable SQLite regression. `CoreDataFieldCheckRepository` / M7 and M12 direct Field Check contracts own the full direct-library identity and relationship checks. M9 Home contracts own warning selection, finding count, preview, history indicator, refresh and UI. Prior M12 Home finding/check contracts own those child UUID identities, not session identities. No writes, data repair, entity model changes, cross-Herd migrations, SwiftData, synchronization, navigation, or change to unrelated Dashboard, Working, or Pasture readers.
