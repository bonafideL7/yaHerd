# Settings save-and-close navigation — behavioral coverage matrix

## Design and production call graph

- The Settings sheet is mounted from `AppNavigationPresentationModifier.sheetContent(.settings)` as `NavigationStack { SettingsView() }`; `AppNavigationState.dismissSheet()` is the one authoritative sheet dismissal. The current `ToolbarDoneButton` is attached to the root `SettingsView` in the presenter, so it is not consistently present on pushed destinations.
- `SettingsView` navigates to `DashboardRulesView`, `HerdSetupView` (then `TagColorLibraryView`), `PastureDefaultsView`, and `AboutYaHerdView`. Place one shared confirmation-toolbar modifier directly on each page; `TagColorLibraryView` must only show it when presented within the Settings sheet, since Home Setup Suggestions also open that view outside Settings.
- `SettingsView` now routes Hard Delete Animals through `SettingsView → HerdSetupView` rather than rendering it at the Settings root. `HerdSetupView` uses the same injected `ApplicationSettings.hardDeleteAnimals` binding and `.disabled(dataAccessMode.isRecoveryMode)`. Its setting continues to be read by animal list swipe/delete decisions; only visual placement changes.
- `HomeView+SetupSuggestions.setupSuggestionRow(.enableDashboard)` opens `DashboardRulesView()` directly through `HomeSuggestionNavigationRow`, not through `AppNavigationPresentationModifier.sheetContent(.settings)`. The toolbar modifier must remain inert when `AppNavigationState.presentedSheet != .settings`, retaining Home navigation and the existing dashboard toggle state.
- `ApplicationSettings` writes validated toggle/stepper updates to `ApplicationSettingsStore` immediately. The checkmark completes/closes the Settings presentation; it must not claim to stage, overwrite, or re-save preferences. All existing write timing, validation, and recovery-mode read-only disabling remain authoritative.
- `TagColorEditorView` is a separately presented editor sheet from `TagColorLibraryView`. Its existing Save validates name/prefix and calls `TagColorLibraryStore.upsert` to persist through Core Data. When launched inside Settings, successful save should close the enclosing Settings sheet as well, while failed writes and invalid input must not close it. Outside Settings, successful Save continues dismissing only the editor.
- The tag-color write has two independently failing operations: a Core Data repository mutation and its subsequent `fetchColors()` projection reload. `TagColorLibraryStore.performRepositoryWrite` previously conflated these in one `do/catch` and the editor interpreted any `lastErrorMessage` as a failed save. Make the store return an explicit mutation success result independent of projection refresh, keeping the last valid color list if refresh fails. Preserve meaningful error messages for failed writes versus committed-but-unrefreshed library data. Apply the same post-write separation to `setDefaultColor`, reorder, delete and restore since they share this helper.
- Use the existing `ToolbarDoneButton` checkmark and `AppNavigationState` navigation environment rather than introducing a new settings draft, transaction, coordinator, or persistence layer.

## Verification and ownership

- This PR changes Settings presentation and clarifies the existing TagColorLibraryStore's distinction between successful Core Data writes and failed view-model refreshes; it does not change TagColorRepository/Core Data mutation semantics, ApplicationSettings, schema, migrations, preference keys, or introduce a settings transaction or global cache.
- Source-review paths: open Settings from Home/Dashboard/Herd/Search; checkmark from root/Dashboard/Herd/Pasture/About/Tag Colors; press Back and remain in Settings; move Hard Delete under Herd Setup, verify root has no duplicate and read-only disabling is retained; change multiple auto-saved settings; enter Dashboard Setup and Tag Colors from Home setup outside Settings (no checkmark, Back works); edit/add tag color in Settings and outside; empty-name validation, Core Data upsert failure, successful upsert followed by library-refresh failure, and recovery via TagColorLibraryStore.refresh; read-only recovery mode.
- Actual iOS runtime navigation, device behavior, build, tests, and CI **not executed** per repository `AGENTS.md` without user authorization.
