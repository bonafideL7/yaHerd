# Pasture Checks All — chronological timeline (follow-up to merged PR #198)

## Design and boundaries

- PR #198 removed the completed-history cutoff but retained attention/open/completed/archived section partitions; All still resembled a prioritization filter, rather than a complete timeline.
- All now renders one chronological section including every fetched check, sorted by its displayed completion time (if complete) or start time (if open), with deterministic ties. Every All row opens the full check overview.
- Scoped Open, Findings, Flagged and Missing filters retain their existing membership and focused navigation. Summary metrics remain independent: attention is not a lifecycle state.
- Existing Core Data FieldCheckRepositoryContract owns all-sessions fetch, status snapshots and archive persistence; AppNavigationStateTests own routing; PR #196 owns visual contrast and grid geometry. This PR owns only All projection, display and row-launch behavior.
- Summary data only includes unresolved findings count; resolved findings remain accessible in session detail. No schema, repository, working flow, migration, synchronization or Home/Dashboard changes.
- Per AGENTS.md, do not run builds, tests, or verification without explicit authorization; review source and diff statically.

## Acceptance conditions

- All displays a single All Checks (N) section, with every fetched UUID exactly once. All statuses and archived pastures are interleaved by displayed activity date; no 12-item cap.
- Its overview keeps Attention/Open/Completed/Archived counters independently derived from the same source, with archived counted separately and completed-with-attention counted as completed.
- Each row exposes the available status and counts (seen/expected, remaining if open, missing, flagged, open findings), and launches the full check rather than an issue-filtered subpage.
- Herd/Search/Home/isolated callers use the shared FieldChecksView; mutation observation and pull-to-refresh continue to reload; scoped filters preserve their focused launch behavior.
- No data, timestamps, session IDs, or persisted fields are changed.
