# Milestone 11 — Retire Dormant SwiftData Tag Color Repository and Legacy Test Suite

## Before implementation — production dependency audit

The active app composes `CoreDataTagColorRepository` and a `MutationPublishingTagColorRepository`; there is **no runtime call** to `SwiftDataTagColorRepository`. The retired adapter was also the only caller of `TagColorDuplicateResolutionPolicy` (`newestNonDefaultWins` / `stableSortOrderWins`); after deleting it, the policy declaration itself is dead code. Keep the live `TagColorLibraryRules` normalization methods and `TagColorDefaults` constant UUIDs unchanged. Source search finds its declaration and one executable consumer, `TagColorLibraryStoreTests`, which uses `SwiftData.ModelContext`. All twelve persistence-neutral Tag Color assertions are already wired to Core Data and pass on merged PR #132. Subsequent current-main Core Data Tag Color tests cover post-staging failure, seven cross-feature UUID references and fresh-context recovery. PR #133 preserves hidden-color identity in edit and Working replacement.

The **still-live UI/store contract** now has three direct Core Data test cases in `CoreDataTagColorRepositoryContractTests` (virtual White/no physical write; Blue selection with one physical default and fresh reload; retired names not in built-in palette), added before deleting the obsolete suite. Do **not** claim the old SwiftData maintenance-on-read side effects are active Core Data behavior: automatically replacing nil legacy tag IDs on library load or normalizing old persisted Black/Brown/Gray rows belongs to a future **lossless legacy database upgrade**. Keep the underlying legacy model/schema and original database bytes for that work.
