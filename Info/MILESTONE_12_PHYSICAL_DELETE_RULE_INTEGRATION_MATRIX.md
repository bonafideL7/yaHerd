# Milestone 12 — Physical Core Data Delete-Rule Integration Contracts

## Design, ownership, and scope

The model-structure suite already checks declared `cascade` and `nullify` rules. M4–M8 feature repository contracts cover feature-directed mutations, including Field Check historical behavior, Working lifecycle and transactional pasture deletion. This focused Milestone 12 slice verifies what **Core Data actually persists after deleting the underlying managed object**, using the production `CoreDataPersistenceAssembly`, a separate transaction and a fresh read context. These are foundation-level relationship guarantees, not alternate deletion workflows. No app runtime, schema, repositories, UI, recovery, legacy source or user files change.

- **This PR owns** physical delete-rule execution for a deleted Pasture and a deleted Animal, independent of feature commands. Every referenced historical record must retain its application UUID and immutable display snapshots while the physical live relationship becomes `nil`; genuinely owned tag/movement rows must cascade. Verify unrelated control records are unchanged.
- **Existing owners:** `CoreDataModelStructureTests` owns the declarative schema; `PastureDeletionTransactionContract`, `FieldCheckRepositoryContract`, `WorkingRepositoryContract` and `AnimalRepositoryContract` own feature workflows, history mutations, business validation and transactional rollback; the M10 startup/recovery contracts own store-load safety. M11/M12 architecture checks own runtime boundary enforcement.
- **Excluded:** creating a new production deletion API, generating movement/history entries by directly deleting a managed object, importing legacy SwiftData data, schema modifications, cloud synchronization, and new global verification entries.
