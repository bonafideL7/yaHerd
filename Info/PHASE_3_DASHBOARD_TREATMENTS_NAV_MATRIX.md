# Phase 3 navigation — historical behavioral coverage matrix

> **Superseded for Dashboard charts (2026-10-17):** The Dashboard chart browse menus, selected-entity actions, and cross-screen chart routing introduced in PR #190 were explicitly rejected and reverted. The live Dashboard has returned to its pre-Phase-3 chart-only behavior; see `Info/DASHBOARD_CHART_NAVIGATION_REVERT_MATRIX.md`. The **Treatment Sets changes from Phase 3 remain in effect**. The Dashboard navigation rows below document historical PR #190 design, not current functionality.

This matrix precedes production edits. Phase 3 is navigation only: no analytics recalculation, repository change, data mutation, migration, or persistence change.

## Design and constraints

- Dashboard values are projections. Drill-downs must use stable identifiers when available (pasture ID, dam ID, check session ID), or the existing typed list filter for a genuinely matching cohort (animal type, sex, working pen, unassigned pasture, sold/dead status). Do not silently claim year/month/season-specific results when the animal list cannot filter those metrics.
- Dashboard tab actions use existing `AppNavigationState.openAnimalList`, `openPastureList`, `openAnimal`, `openPasture`, and `openFieldCheckArea`. Navigation crosses to YaHerd for animal/pasture lists or isolated workflows for field checks, matching existing Home deep-link semantics.
- Chart-selection menus must offer accessible, labeled buttons independently of chart gestures. Empty charts must not show drill-down actions. Selected categories (animal type, sex, location) must still exist in the current nonempty live projection before showing a follow-up; selections retained across refreshes must not navigate stale cohorts.
- Dam chart categories and selected navigation are keyed by the stable dam UUID string, never by generated tags. A custom chart Y axis renders human-readable dam tags; when raw tags collide with generated disambiguation suffixes, the chart labels also remain unique. The displayed dam and its navigation target must refer to the same UUID. Missing IDs after refresh must hide follow-up actions. Menu choices also navigate by UUID.
- Treatment sets have one visible, consistently named destination within Working Sessions and a Home shortcut grouped under Working Pen. Keep `TreatmentTemplatesView` as the existing editor. Do not add a duplicate toolbar action in the same Working Sessions list.
- Dashboard snapshot observations remain read-only; the mutation stream and refresh control are unchanged. No new persistence or separately owned navigation state.

## Review reconciliation — refresh and identity

- Category-selection follow-ups for animal type, sex and location must be validated against the live nonempty chart values before making a navigation action visible. This is distinct from stale route restoration: these selections are transient local chart UI state, not persisted navigation state.
- The dam chart must use the item UUID as the chart categorical value and the selected value. The generated tag is strictly display text; raw tags already resembling generated suffixes may otherwise collide. The chart-axis label and menus must remain user-distinguishable, and a removed dam must no longer produce a follow-up.
- A regression case belongs in the existing `DashboardPresentationDataTests` suite for tag/suffix collisions; do not introduce a new runner or duplicate tests. Runtime chart selection and live-refresh UI behavior remain unverified because repository policy prohibits running verification without user instruction.
