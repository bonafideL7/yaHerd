# Phase 3 navigation — behavioral coverage matrix

This matrix precedes production edits. Phase 3 is navigation only: no analytics recalculation, repository change, data mutation, migration, or persistence change.

## Design and constraints

- Dashboard values are projections. Drill-downs must use stable identifiers when available (pasture ID, dam ID, check session ID), or the existing typed list filter for a genuinely matching cohort (animal type, sex, working pen, unassigned pasture, sold/dead status). Do not silently claim year/month/season-specific results when the animal list cannot filter those metrics.
- Dashboard tab actions use existing `AppNavigationState.openAnimalList`, `openPastureList`, `openAnimal`, `openPasture`, and `openFieldCheckArea`. Navigation crosses to YaHerd for animal/pasture lists or isolated workflows for field checks, matching existing Home deep-link semantics.
- Chart-selection menus must offer accessible, labeled buttons independently of chart gestures. Empty charts must not show drill-down actions. Chart selections should identify the selected record unambiguously; duplicated display labels never become lookup keys for record navigation.
- Treatment sets have one visible, consistently named destination within Working Sessions and a Home shortcut grouped under Working Pen. Keep `TreatmentTemplatesView` as the existing editor. Do not add a duplicate toolbar action in the same Working Sessions list.
- Dashboard snapshot observations remain read-only; the mutation stream and refresh control are unchanged. No new persistence or separately owned navigation state.
