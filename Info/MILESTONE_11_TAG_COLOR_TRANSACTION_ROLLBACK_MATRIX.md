# Milestone 11 — Core Data Tag Color Post-Staging Rollback Matrix

## Design and trace

All Tag Color mutations use the common `CoreDataTagColorRepository.performWrite` path, which stages inserts/updates/deletes/remapped current/historical references in a private-queue `NSManagedObjectContext`, saves, and rolls back on errors. The M0 permanent Tag Color domain contract and M11 real reference runner (merged PRs #131–#132) cover normal success and pre-validation rejection, but **do not intentionally fail after mutation staging**. That is the remaining transaction contract gap before SwiftData Tag Color retirement.

Add a narrowly scoped **internal, default-nil** `beforeSave` injection point to the existing repository initializer, called only when `context.hasChanges` and after the operation has staged all modifications, but before Core Data save. It does not expand Domain ports, app composition, SwiftData code or production behavior. Tests use `CoreDataPersistenceAssembly.inMemory()`, the existing physical CDAnimalTag/Field Check/Working fixture and a captured rollback context to assert both persisted and same-context recovery. Injection errors must propagate without leaking staged records, and the same repository must remain usable afterward.

## Scope and safety

- **Source:** only `yaHerd/Data/Repositories/CoreData/CoreDataTagColorRepository.swift` internal optional injection seam. No other production mutation semantics, new actor, Domain API or table.
- **Tests:** extend existing `yaHerdTests/CoreData/CoreDataTagColorRepositoryContractTests.swift`, reusing its already established in-memory Herd fixture and real reference probe rather than creating a one-off global verification runner.
- **Legacy:** `SwiftDataTagColorRepository`, remaining SwiftData models, original user SQLite/journals, preflight and read-only export/recovery untouched. Migration of original SwiftData user records is still a separate release blocker.
- **Verification policy:** do not manually run builds/tests/lint/CI under `AGENTS.md`; audit source/diff and let automatic PR verification report actual results.

## Implemented verification and remaining scope

The existing Core Data Tag Color contract runner now contains five grouped injected-failure tests covering custom insert/update, default reassignment, reorder, referenced hide, restore-defaults, and both custom/custom and custom/built-in reference identity merges. A one-shot callback observes staged changes, throws before save, and captures the actual context; after failure the tests require a clean same-context fetch and no-op save, exact fresh-context rollback baselines, and successful retry with the original repository instance. Collision-specific probes ensure physical duplicate deletion, current/retired AnimalTag relinks, Field Check/Working snapshot edits, and Animal editor-revision rotation were staged; rollback is compared against all seven physical reference UUIDs and the original revision.

**Not claimed:** a simulated *Core Data SQLite disk error from within `context.save()`* (the seam throws immediately before save); unrelated-Herd independent control fixtures; and full screen-level active UI rendering. Those remain separate M11 owners. This is test instrumentation only, **not** an automatic migration of original legacy SwiftData users. Verification remains pending automatic PR checks; no manual build/test/lint was run.
