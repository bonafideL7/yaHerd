# Restore dashboard charts without cross-screen navigation

## Reason and design (17 October 2026)

The user rejected PR #190's "drill-downs": chart browse menus and follow-up buttons merely launched YaHerd lists, pasture/animal details, or full-screen Field Check flows, leaving the Dashboard instead of drilling into the chart in place. Undo **all Dashboard chart navigation** rather than replacing the destination with another cross-screen route.

Comparison of `main`, PR #190's base `da1bdfbcc2f40dc06fd01a8ee3d9927ba00236ad`, and its head `abf91426a1de55bc575d4899c1e7a060f6d6c171` confirms the current versions of the three affected Dashboard files are byte-for-byte identical to PR #190's head. Restore **DashboardChartSections.swift** to the exact pre-Phase-3 blob to remove the navigation actions and UUID-based chart selection. Preserve the collision-safe dam label derivation in **DashboardPresentationData.swift** and its existing regression contract in **DashboardPresentationDataTests.swift**: the non-interactive offspring-by-dam bar chart uses the string display label as its categorical Y value, so distinct dams must not receive duplicate labels even if a free-form raw tag collides with an auto-generated suffix. This is a display correctness property, not a navigation feature. Preserve Home/Working Sessions Treatment Sets changes from PR #190.

### Ownership and constraints

- This PR owns removal of Dashboard chart actions/selections/routes introduced in #190, exact restoration of the pre-Phase-3 **chart view**, and preservation of chart-projection label uniqueness with its existing regression test. The Dashboard model and test files remain unchanged from `main`.
- Home, YaHerd, Search, pasture/animal detail, workflow routing, and Treatment Sets remain owned by existing app navigation and PRs #188–#190. This PR does not alter their actions, files or route persistence.
- Later *in-Dashboard drill-downs* would be a separate design request. Do not add a new workaround now.
- No persistence, mutation, schema, networking, Core Data, concurrency, migration, or recovery changes.
- Per `AGENTS.md`, do not run builds, tests, lint, or CI manually absent explicit verification instructions. Static source + diff review only.
