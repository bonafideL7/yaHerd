# Milestone 12 — deterministic persisted pregnancy summary matrix

## Design and ownership

An Animal's Core Data pregnancy checks are an unordered relationship. `CoreDataAnimalProjection.summary` currently selects `max { $0.date < $1.date }` without a tie-break. If distinct checks share a timestamp, the returned status and expected-calving date can vary after context reconstruction, affecting Animal list, Pasture resident lists, maternal offspring summaries and Dashboard/Home derivation. The Working queue editor independently selects the first check sorted by descending date and **ascending** UUID, so its value may disagree with Animal summary for the same equal-dated history.

Use the already established Working-editor tie policy in both projections: latest date first, and **lexicographically smallest persisted check UUID** on an equal date. The Animal summary `max` predicate should therefore order larger UUID *before* smaller UUID on ties. No schema, writes, stored UUIDs, history, pregnancy fallback calculation, or unrelated read models change. This is a read-model consistency contract with M5 owning pregnancy writes/history and M9 owning Dashboard/Home read reductions.
