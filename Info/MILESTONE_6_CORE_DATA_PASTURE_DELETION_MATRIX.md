# Milestone 6 — Core Data Pasture Deletion and Movement Coverage Matrix

This matrix is the implementation/review inventory for Milestone 6. It covers the Core Data Pasture deletion transaction and the reusable Core Data Animal movement behavior required by Pasture workflows. The running app remains on SwiftData until Milestone 10.

## Ownership

### Owned by this milestone

- Core Data `PastureDeletionTransactionWriting` executing one normalized Domain-authored plan in one write scope and one final save.
- Revalidation of every `PastureDeletionExpectedState` before mutation.
- Reusable Core Data Animal movement semantics needed by Pasture deletion: current-pasture replacement, movement-history snapshots, Working ownership release where the declared movement semantics require it, and Animal editor-revision rotation.
- Relationship cleanup caused by deleting Pastures, including inactive/archived Animals that are not members of the active resident move set.
- Preservation/archival of Field Check Pasture history required by the existing Core Data model and permanent deletion contracts.
- PastureGroup survival when its last Pasture is deleted.
- Pasture-related live Working relationships nullifying through the Core Data model while historical snapshots remain durable.
- Rollback/recovery, stale-state rejection, cross-feature Animal revision invalidation, and mutation-boundary behavior for the transaction.

### Delegated / owned elsewhere

- Field Check repository CRUD and runtime projections: Milestone 7.
- Working repository CRUD and transaction behavior: Milestone 8.
- Dashboard, Home, paged Animal-list and other performance query implementations: Milestone 9. M6 preserves the durable graph those readers consume.
- Runtime dependency cutover and `DeletePasturesUseCase` production wiring to Core Data: Milestone 10.
- SwiftData is transitional and is not an M6 implementation target.

## Verification status

All M6-owned cells marked “Implemented; unverified pending M6 runner” describe production behavior now present on the branch but not yet protected by the declared Core Data M6 runner. They must not be treated as contract-verified until that runner invokes the permanent success, stale-precondition, rollback, cross-feature revision, concurrency, and mutation-boundary controls.

## Matrix notes

- The transaction executes the Domain-authored plan; persistence must not rediscover which residents should move or invent additional workflow operations.
- Expected resident sets mean active, unarchived Animals, matching the existing `PastureResidentAnimalReader` contract.
- Inactive/sold/dead/archived Animals that still reference a target Pasture are relationship-cleanup survivors, not Domain-authored move residents. They receive revision rotation when the relationship is cleared but no synthetic movement record.
- M6 may manipulate existing Core Data Field Check/Working managed objects only as required for Pasture deletion relationship/history correctness. It does not implement M7/M8 repositories early.
- The running application remains SwiftData until Milestone 10.
- Verification is not run unless explicitly requested.
